# 首次引导可选渠道配置规格

日期：2026-08-08

## 目标

让用户决定是否在首次引导中配置 OpenClaw 官方消息渠道，不再静默跳过官方已支持的可选能力。

## 协议约束

- 只调用官方 `wizard.start` 的 `flow: "channels"` 流程。
- 渠道步骤继续使用官方 `wizard.next`、`wizard.status`、`wizard.cancel`。
- 不新增 RPC、配置字段、渠道账号模型或本地成功状态。
- Gateway 返回的 `accounts` 是唯一的已配置账号证据；空数组只能表示本次没有返回账号，不得推断“全部未配置”或“全部成功”。

## 页面状态

`decision` 允许配置或稍后配置；`active` 呈现官方步骤；`completed` 展示官方返回的账号数量；`error` 展示真实错误并允许重新开始或稍后配置。离开页面会取消当前会话并清理本地呈现状态，不删除 Gateway transcript 或配置。

## 验收条件

1. 模型核验通过后必定进入渠道决策页。
2. 用户选择配置后，发送 `wizard.start { flow: "channels" }`，不附加未证明字段。
3. 用户选择稍后后不产生渠道配置副作用，并可在工作台“通道”入口再次使用官方渠道流程。
4. 加载、失败、取消、会话失效和成功状态均有三套语言文案。
5. 核心模型向导与渠道向导共用同一结构化步骤组件。
