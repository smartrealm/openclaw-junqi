# 协作 schema 12/14 恢复规格

## BUG-01：schema 12 安全升级

**当前**：schema 12 被当成未知版本拒绝，协作 service 启动失败。

**目标**：仅当数据库对象集合精确匹配仓库历史 schema 12 时，先创建不可覆盖的私有备份，再在单个
事务内迁移到 schema 15。迁移复用 schema 13 的删除收据与会话命令收据归并规则，并由当前 schema
创建模板表、命令可用索引和当前墓碑约束。成功后记录迁移来源；任一校验失败不修改原库。

**验收**：

- [x] 合法 schema 12 可升级到 schema 15，并保留可映射收据。
- [x] 升级前创建 schema 12 一致性备份，权限为私有。
- [x] 非法 schema 12 结构、收据冲突和无效墓碑均不提交升级。
- [x] schema 11、未来版本和结构漂移继续失败关闭。

## BUG-02：钉钉核验证据最小化

**当前**：运行页常规展示完整 Session key 和插件版本，容易被误解为业务成功证据。

**目标**：常规区域仅展示 Session 已核验、当前 Agent 与当前 Session 可用工具数。内部路由身份和
插件版本仅在默认收起的技术详情中显示，并使用现有主题 token 与原有键盘可访问语义。

**验收**：

- [x] 常规界面不包含完整 Session key 或插件版本字符串。
- [x] 技术详情可按键盘展开，包含实际 Session key 与版本用于诊断。
- [x] 页面继续说明 DWS 就绪、Gateway 健康和审计未知态均不等同于钉钉业务结果。

## BUG-03：schema 14 命令索引门禁

**当前**：对象门禁和测试夹具都从 schema 14 删除 `commands_available`，真实 schema 14 因多出该合法
索引而在迁移前被拒绝。

**目标**：schema 12、13 的预期对象集合不包含该索引；schema 14 的预期对象集合必须包含仓库历史源码
定义的 `commands_available`。其他额外或缺失对象继续失败关闭。

**验收**：

- [x] 由真实历史对象集合构造的 schema 14 可迁移到 schema 15。
- [x] schema 14 私有备份包含 `commands_available`。
- [x] schema 12、13 仍按各自历史结构迁移，不伪造该索引。
- [x] schema 14 缺失该索引时继续按结构漂移拒绝，原库不提交修改。
