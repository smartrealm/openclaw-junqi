# OpenClaw 浏览器控制规格

日期：2026-08-05

## 目标

在 JunQi 会话顶部工具组提供简洁的“浏览器”入口，忠实调用 OpenClaw Gateway 的
`browser.request` 协议，以查看并控制 Gateway 已声明的浏览器 profile、运行状态和标签页。

## 约束

1. 当前安装的 OpenClaw 包只能作为协议核对依据；客户端不得根据版本号启用、禁用或改写功能。
2. 所有请求仅通过 `browser.request` 发送，参数严格限制为官方 HTTP 代理字段；不发送未经
   协议证实的 profile 创建、删除或持久化修改请求。
3. 浏览器控制使用短时 `operator.admin` 请求器，不提升日常 Chat 连接的权限。
4. profile、状态、标签页和快照必须来自 Gateway 返回；未知方法、连接中断或返回结构非法时
   不得伪造本地成功状态。
5. 未运行的浏览器只读取状态，不请求标签页；运行中的标签页读取失败必须保留错误，不以空列表
   伪装为成功。
6. 打开、聚焦、关闭标签页和读取快照等可能访问既有登录态的操作，对 Gateway 标记为
   `existing-session` 或 `extension` 的 profile 必须经本机用户确认。
7. URL 只接受绝对 HTTP 或 HTTPS 地址；拒绝本地文件、相对路径和未知协议。
8. 入口、按钮、Tooltip 和提示文案必须使用三语言资源；入口名保持为“浏览器”及同等简短翻译。

## 验收条件

- 会话顶部仅出现一个浏览器图标入口，Tooltip 使用本地化短名称。
- 用户可选择 Gateway 返回的 profile，查看运行状态，在可用时启动、停止、打开、聚焦、关闭标签页
  及读取页面快照。
- 浏览器未启动、Gateway 不支持、连接断开、权限未批准和协议返回非法时，界面展示明确失败状态，
  不发生隐式降级、自动重试或本地伪造。
- 既有登录态 profile 的受影响操作显示确认；隔离 profile 不额外打断正常操作。
- 自动化覆盖请求形状、URL 和路径约束、不可用映射及响应解析；真实 Gateway 与目标平台验证另行记录。
