# 安装、仪表盘、聊天、模型与渠道运行时边界规格

## 目标

让配置、安装、Gateway 数据、渠道、提供商和 Chat 都以当前选定 runtime 的权威响应为准，并保证迟到事件、并发配置写入和结构化历史消息不会破坏用户可见状态。

## 验收条件

1. OpenClaw 配置读取、验证和写入接受 JSON5，且拒绝不符合已知对象形状的配置。
2. 读取和写入只针对当前选定 runtime 的配置路径；页面不能指定任意本地配置路径。
3. 写入使用 revision 比较；过期写入失败并要求重新读取，不能静默覆盖外部更新。
4. 前端不得持久化完整 OpenClaw 配置、provider key 或渠道凭据。
5. 渠道保存不得删除 `defaults`、`modelByChannel` 或未编辑的最新渠道/绑定；冲突重试有上限。
6. 提供商目录和模型选择只使用当前 runtime 或 Gateway 的实时权威数据，不使用跨 runtime 缓存或静态兜底目录伪装为当前来源。
7. 一个 Setup operation 只能接收自己的进度事件；重试、取消或替换后旧事件不得改变当前步骤。
8. 持久化安装诊断不得保存未脱敏的凭据。
9. Gateway 轮询结果必须同时匹配当前连接对象和该数据组的最新请求；断开后不得回填数据。
10. Gateway uptime 在 Dashboard 重挂载后保持同一连接起点，并在断开时归零。
11. Chat 工具卡和追溯保留上游提供的工具 ID、状态、错误、时间和截断事实；不得生成伪 ID 或伪审核记录。
12. 结构化历史 `toolResult` 显示实际结果内容，不能显示其外层传输数组。
13. 文件卡片使用共享 workspace 文件类型领域逻辑，Chat 气泡不得保留另一份扩展名分类表。

## 失败关闭

- 配置解析、revision 或 runtime 选择失败时，页面展示错误并不写入替代路径。
- 无法确认 Gateway 连接或请求新鲜度时，不更新对应仪表盘数据。
- 无法确认正式审核关联时，只显示 transcript-only 信息，不显示可执行审核动作。
- 无法安全保存渠道时，编辑器保持打开，用户输入不被无声丢弃。
