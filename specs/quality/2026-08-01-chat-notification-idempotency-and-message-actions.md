# Chat 通知幂等与消息操作栏

## 问题

同一助手回复可由流结束和持久转录重复触发通知，助手气泡的操作按钮会覆盖正文。

## 验收条件

- 相同 Gateway 事件身份最多写入一条通知并最多触发一次前台提示。
- 通用 `onMessage` 回调不得作为聊天通知生产者；它缺少稳定运行身份且可能镜像流事件或持久转录。
- 持久 `session.message` 已携带的 `runId` 必须优先用于匹配同一回复的流结束通知。
- 已完成实时运行的后续持久转录必须按事件 `runId` 识别为已投影，即使转录内的客户端或原生消息 ID 不同。
- 缺失外层 `runId` 的旧 Gateway 持久镜像，只有在同一会话的短时实时完成正文严格匹配时才可识别为已投影；该规则不得跨会话，也不得抑制重连后的纯转录通知。
- 正常路径必须按 Gateway 身份去重；当旧 Gateway 将同一回复镜像为不同消息 ID 时，仅同一聊天会话、同一角色、同一标题和正文且在两分钟内的 `chat:*` 记录可以合并。该兼容规则不得作用于无身份通知、不同会话、不同角色或超过窗口的回复；未知身份或空正文的聊天事件不得发布通知。
- 通知 IPC 的 `dedupeKey` 与 Rust `dedupe_key` 序列化字段一致。
- 通知写入结果必须明确返回是否新增；声音、toast 和后台提示仅在新增时呈现，不能在持久层拒绝重复后仍产生第二次可见提示。
- 读取持久通知时，完全相同的历史 `dedupeKey` 只能显示一条，且保留最新记录；上述受限的不同消息 ID 聊天镜像也只能显示最新一条。仅对旧版本留下的相邻、无键、所有展示与跳转字段相同且在实时终态与持久转录镜像的两分钟容忍窗口内产生的重复记录，可以保留最新一条；其他无键记录不得按展示文本合并。
- 持久通知的读取、推送、已读和清空必须只经过 typed repository；终端和普通通知中心不得直接调用通知 command。
- 预览、复制操作栏可见且不覆盖助手消息正文。
- TypeScript 与 Rust 回归测试通过。
