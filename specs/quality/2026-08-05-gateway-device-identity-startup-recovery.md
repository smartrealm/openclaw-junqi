# Gateway 设备身份与工作区启动恢复规格

## 目标

在不改变 OpenClaw Gateway 设备挑战协议的前提下，减少同一桌面进程内重复系统凭据库访问，
并确保已完成安装的客户端在 Gateway 最终连接失败时能够进入真实的可恢复离线界面。

## 约束

- JunQi 只作为 OpenClaw 客户端，不新增或伪造 Gateway 认证协议。
- 私钥只保留在操作系统凭据库与 Rust 进程内存中，禁止进入渲染进程、日志、持久化文件、
  文档或测试快照。
- 无设备签名时必须 fail-closed，不得回退为 token-only `connect`。
- 只缓存成功结果；凭据库错误、拒绝或损坏身份不得被缓存为成功或永久失败。
- 只有 `setupComplete` 且缓存安装验证已结束时，Gateway 重试穷尽才能放行工作区。

## 验收条件

- [x] 同一进程首次成功初始化设备身份后，后续签名调用复用该身份，不再次触发初始化器。
- [x] 设备签名失败仍不发送 `connect`，保留既有失败关闭行为。
- [x] 已完成安装且验证结束时，连接重试穷尽会释放工作区启动遮罩并提交 connection 错误状态。
- [x] 未完成安装或仍在缓存安装验证时，连接重试穷尽不放行工作区。
- [ ] 在 macOS、Windows、CentOS/Ubuntu 的真实 Desktop 安装包上验证系统凭据授权与手动恢复。
