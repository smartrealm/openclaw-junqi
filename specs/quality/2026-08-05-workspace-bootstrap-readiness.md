# 工作区首屏数据就绪规格

日期：2026-08-05

## 目标

首次进入非 Gateway 可选页面时，JunQi 必须先完成当前 Gateway 连接的会话与智能体首批数据同步，
再渲染仪表盘、侧栏会话和其他工作区界面。

## 约束

1. `sessions.list` 写入 Chat 会话投影后，仍须等待共享会话和智能体数据组在当前连接周期完成成功读取。
2. 断线前的 `lastFetch` 不得作为新连接的启动就绪证据；数据时间必须不早于当前连接开始时间。
3. 会话或智能体首次读取失败时，不能把空壳仪表盘作为降级成功状态。应保留全局错误与明确重试入口。
4. 设置、终端、日志等 Gateway 可选页面保持原有可访问性。
5. 历史消息和模型目录仍在工作区放行后后台同步；它们不是会话目录和智能体目录的替代门禁。
6. 加载和失败界面复用共享全屏 fallback，文案使用三语言资源。

## 验收条件

- 首次进入仪表盘不会先显示空会话侧栏或空智能体卡片，再异步补数据。
- 当前连接的会话、智能体快照全部成功后才渲染工作区。
- 首批读取失败时显示全局失败和重试，不渲染半成品仪表盘。
- 重试会重新请求 Chat 会话快照以及共享会话、智能体数据组。
