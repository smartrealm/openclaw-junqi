# OpenClaw 智能体作用域会话侧栏规格

日期：2026-08-09

## 当前行为

- 会话侧栏混合展示所有智能体会话。
- 主会话参与普通活动排序。
- 分类呈现同时依赖 `category`、派生 `groupId` 和日期分桶。
- 新建会话根据当前活动会话推断智能体。
- 侧栏没有分组、排序和“所有会话”入口。

## 目标行为

### BUG-SS-01 · 智能体作用域

- 顶部显示来自 `agents.list` 的智能体选择器。
- 列表只展示当前选中智能体的会话。
- 点击其他智能体的会话后，选择器同步到该会话所属智能体。
- 新建会话明确绑定当前选中的智能体。

### BUG-SS-02 · 主会话固定

- 使用 Gateway 已确认的主会话 key。
- 当前智能体主会话存在时固定为第一行，不参与普通分组和排序。
- 不拼接或猜测不存在的主会话 key。

### BUG-SS-03 · 单一分组来源

- 按自定义分组时，`category` 非空的会话只出现于对应分类。
- `category` 为空的会话只出现于未分组区域。
- 侧栏只读取 OpenClaw `category`，不再读取派生 `groupId` 或日期分桶状态。

### BUG-SS-04 · 官方分组与排序

- 分组依据支持“自定义分组”和“不分组”。
- 排序方式支持“创建时间”和“最近更新”。
- 置顶会话保持独立区域；主会话仍优先于置顶和普通会话。

### BUG-SS-05 · 所有会话

- 侧栏底部固定显示“所有会话”。
- 点击后进入现有 `/sessions` 完整会话管理页。

### BUG-SS-06 · 智能体管理操作

- 智能体作用域菜单同时展示可选智能体、新建智能体和当前智能体设置。
- 新建智能体进入现有 `/agents?new=1` 流程。
- 当前智能体设置进入现有 `/agents?agent=<id>` 详情，不增加本地智能体写入协议。
- 智能体列表暂不可用时仍允许进入新建智能体流程。

### BUG-SS-07 · 稳定创建顺序

- 存在 `createdAt` 时按 Gateway 创建时间倒序排列，不得由首次活动顺序覆盖。
- 缺少 `createdAt` 的旧会话不能使用首次接收顺序、本地时间或新建后的本地提升伪造创建时间；它们
  保持 Gateway 本次返回的相对顺序，并排在可核验创建时间之后。
- 新建会话仅在 `sessions.create` 回执含有 `entry.createdAt` 时投影创建时间；不得由 `updatedAt` 或
  客户端时钟补值。
- 当前作用域没有任何可核验 `createdAt` 时，“创建时间”不可选择，并显示 OpenClaw 未返回该字段的
  真实原因；不自动宣称已按创建时间排序。
- 最近更新排序继续使用 Gateway 返回的活动或更新时间，不与创建顺序混用。

### BUG-SS-08 · 排序与时间显示一致

- 选择“创建时间”时，每行的时间列只显示该行的 `createdAt`；字段缺失时显示不可用状态，不得显示
  `updatedAt` 或最近活动时间。
- 选择“最近更新”时，每行的时间列使用 Gateway 活动或更新时间。
- 主会话固定和置顶分区不改变其时间字段的真实含义；它们只改变布局位置。

### BUG-SS-11 · 创建时间的跨界面一致性

- 会话详情的“会话时长”只依据 `createdAt` 计算；字段缺失时显示未知。
- 历史活动投影可以保留最近活动或更新时间，但不得将其写入 `createdAt`。

### BUG-SS-12 · 路由新建会话的首屏隔离

- 带 `?agent=<id>&new=1` 的新建意图在 Gateway `sessions.create` 确认前，不得挂载上一个活动会话的
  历史或输入框。
- 创建中只呈现当前路由的创建状态；失败时保留原路由意图并在原位置提供显式重试。
- Gateway 确认会话身份后才消费该路由参数，随后进入已确认的空 transcript 会话。

### BUG-SS-09 · 全局会话作用域

- 会话读取以 `agents.list` 已确认的智能体身份为范围；每个智能体的活动和归档会话都通过带
  `agentId` 的官方 `sessions.list` 读取，并明确请求 `includeGlobal`。
- Gateway 返回 `key === 'global'` 的行只有同时具备本次请求已确认的智能体身份时，才能进入
  JunQi 会话投影。投影身份使用 OpenClaw 官方 Control UI 已采用的
  `agent:<agentId>:global` 作用域别名；普通会话 key 不改变。
- 全局会话的历史、发送、Stop、会话设置、组织操作、生命周期操作、检查点、产物和事件处理，必须
  从该作用域身份还原同一个 `{ key: 'global', agentId }` RPC 目标。
- 缺少可核验全局会话所有者时，JunQi 不加载历史、不发送、不停止、不写入，也不把它显示为默认智能体。
- 所有本地消息、草稿、队列、流、运行、删除和缓存键必须使用作用域身份；不同智能体的全局会话不能
  共享本地状态。

## 验收条件

- 不同智能体的会话不会在当前侧栏混排。
- 切换智能体后列表、新建会话目标和主会话入口使用同一智能体身份。
- 分类会话不会重复出现。
- 两种分组方式和两种排序方式均有行为测试。
- 主会话固定第一且不存在时不生成伪会话。
- `/sessions` 入口支持键盘访问并具有可访问名称。
- 智能体菜单中的切换、新建和设置均支持键盘访问并具有可访问名称。
- `createdAt` 与当前活动顺序冲突时，创建排序必须以 `createdAt` 为准。
- 缺少 `createdAt` 的会话保持 Gateway 返回顺序，不生成本地创建顺序。
- `sessions.create` 缺少 `entry.createdAt` 时，刷新前后都不得显示或排序为具有创建时间。
- 当前范围没有 `createdAt` 时，创建排序控件清晰显示不可用，最近更新仍可选择。
- 创建排序时，行尾时间与 `createdAt` 一致；最近更新排序时，行尾时间与 Gateway 活动或更新时间一致。
- 会话详情和历史活动数据不会把 `updatedAt`、最近活动时间或客户端时间展示为创建时间。
- 路由新建会话期间不会显示或加载此前活动会话的历史；失败后可在原页面重试，成功后才进入新会话。
- 亮色、暗色、窄侧栏、空列表和加载状态使用现有主题 token。
- 多个智能体都拥有 `global` 会话时，列表、历史、消息、Stop、删除标记、流式输出和发送队列彼此隔离。
- 缺少 `agentId` 的 `global` 结果不会被投影为默认智能体，也不会触发写操作。
- 首次 Gateway 连接时，`agents.list` 的有效快照必须先于按智能体范围的会话读取；空范围等待不得显示为
  会话列表加载失败，真实会话 RPC 错误仍须可见。

## 本轮验证

- 定向测试验证 `createdAt` 被严格保留，负数时间被拒绝，创建排序不会退化为最近活动排序。
- 定向测试验证主会话与置顶会话的布局固定不改变普通会话的创建时间排序契约。
- 定向测试验证多智能体裸 `global` 行被投影为彼此隔离的作用域别名；订阅和会话解析向 Gateway
  发送规范 key 与对应 `agentId`。
- 真正多智能体 Gateway 与 macOS、Windows、Linux 桌面窗口的端到端和视觉验证尚未完成。
