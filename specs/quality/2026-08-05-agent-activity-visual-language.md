# Agent 活动视觉语言规格

日期：2026-08-05

## 问题

Chat、灵动岛和 Agent Hub 使用通用 Spinner 表达智能体活动，无法区分思考、生成、工具执行和语音活动；部分区域还为同一状态叠加多套循环动画。直接全局应用第三方 Orb 或 Border Beam 又会破坏加载语义、主题一致性和性能边界。

## 目标行为

1. Agent 活动和普通异步加载使用不同共享组件。
2. 只根据结构化状态表达 `thinking`、`generating`、`working` 和 `listening`。
3. Chat、灵动岛和 Agent Hub 使用同一活动图形语言，同一状态区域只保留一个主要循环动画。
4. 四个 Aegis 主题使用应用当前主题，而不是操作系统主题。
5. Reduced Motion 下停止持续动画并保留静态可识别图形。
6. 空闲、完成、失败和等待用户处理继续使用稳定的品牌或状态图标。

## 约束

- 不改变 Gateway、Tauri IPC、Store、会话和任务状态契约。
- 不从文案或不稳定工具名称推断搜索、连接、求解等阶段。
- 不替换按钮、设置、文件、Provider、渠道和普通网络请求的 `LoadingIndicator`。
- 不引入 Border Beam 依赖；活动区域强调只能使用 Aegis 语义 Token。
- 图形不能截获指针，不能成为唯一状态表达，也不能重复朗读可见文案。
- 业务代码只能调用 JunQi 包装组件，不直接导入第三方组件。

## 验收条件

- [x] `AgentActivityIndicator` 仅开放四种受控业务状态。
- [x] Chat 思考和执行汇总接入活动图形并移除重复三点动画。
- [x] 灵动岛依据现有投影阶段接入活动图形并移除重复 Spinner。
- [x] Agent Hub 聚合运行状态接入活动图形，普通加载保持不变。
- [x] 第三方版本锁定并记录 MIT 归属。
- [x] 状态映射、主题映射和无障碍回归测试通过。
- [ ] 四主题、窄窗口、系统 Reduced Motion 和低性能 Windows 真机验收通过。
