# 智能体工作区文件能力修复规格

状态：代码与自动化完成，待桌面交互验收

日期：2026-07-27

## 用户流程

1. 用户打开智能体工作区右侧“文件”面板。
2. 单击文本文件后，中心区域打开标签；Markdown 默认显示安全渲染预览，其他文本显示编辑器，图片显示只读预览。
3. Markdown 可在“预览/编辑”之间切换；文本编辑显示保存状态，可点击保存或按 `Ctrl/Cmd+S`。
4. 智能体或其他程序修改已打开文件时，干净标签自动刷新；脏标签保留草稿并要求用户选择磁盘内容或本地内容。
5. 用户右键文件或目录时，菜单始终显示在窗口可见区域；空白处右键作用于项目根。
6. 文件或目录可新建、重命名、复制路径、在系统文件管理器中显示或移到系统废纸篓。

## 右键命令矩阵

| 目标 | 新建文件/目录 | 打开 | 重命名 | 复制路径 | 系统中显示 | 删除 |
| --- | --- | --- | --- | --- | --- | --- |
| 项目根/空白 | 是 | 否 | 否 | 是 | 是 | 否 |
| 目录 | 是 | 否 | 是 | 是 | 是 | 是 |
| 文件 | 在父目录创建 | 是 | 是 | 是 | 是 | 是 |

“打开”与左键行为一致，仅对文件显示。目录左键继续展开/折叠。

该矩阵适用于以下全部文件树入口：

- 智能体工作区右侧文件面板；
- 文件管理页的树视图；
- 智能体详情展开后的工作区文件树；
- 终端页工作区文件树。

所有入口由同一个纯命令模型决定菜单项，并由同一个 Portal 菜单渲染。页面可以追加不改变核心矩阵的专属动作；当前仅终端页追加“插入路径到终端”。空白处、空目录提示和加载失败提示区域的右键目标都是项目根。智能体详情操作已打开文件或其父目录前必须先完成相关脏内容写入；写入失败时取消重命名或删除。

## 重命名 IPC 合约

命令：`rename_path`

前端参数：

```ts
{
  path: string;
  newName: string;
  projectPath: string;
}
```

返回：重命名后的绝对路径字符串。

约束：

- `path` 必须是 `projectPath` 内现存条目。
- `newName` 必须是单一合法路径组件。
- 不允许项目根、`.git` 或 `.junqi` 第一层目录及其后代被重命名。
- 不跟随项目内链接去重命名项目外目标；重命名的是目录项本身。
- 目标已存在时拒绝，不覆盖。

## 标签同步

- 文件重命名：把完全匹配的打开标签改为新路径和新文件名。
- 目录重命名：把目录下所有打开标签的路径前缀替换为新目录路径。
- 文件/目录删除：关闭完全匹配或属于被删目录的标签；若活动标签被关闭，选择剩余标签的最后一项，否则返回任务视图。

## 受保护写入 IPC 合约

命令：`write_file_content_if_unchanged`

前端参数：

```ts
{
  path: string;
  content: string;
  expectedContent: string;
  projectPath: string;
}
```

返回：磁盘内容仍等于 `expectedContent` 并完成写入时为 `true`；基线不匹配时为 `false`，且不得修改磁盘文件。

该命令是文件内容级乐观并发门禁，不声明为跨进程原子 CAS。前端在成功写入后必须回读磁盘，随后仍由目录 watcher 处理更晚发生的外部写入。

## 保存语义

- 保留延时自动保存。
- 文本内容与最近成功写盘内容不同时显示未保存/保存中状态并启用保存按钮。
- 保存按钮和 `Ctrl/Cmd+S` 立即进入同一条串行保存队列，并调用 `write_file_content_if_unchanged`。
- pane 卸载时若仍有未保存内容，也进入同一条串行保存队列；不得绕过队列并发写入，不对图片或加载失败内容写盘。
- 磁盘内容偏离最近一次成功保存的基线且本地也有修改时，暂停延时保存、立即保存和卸载写回，避免静默覆盖外部写入。
- “从磁盘重新加载”丢弃本地草稿并读取最新磁盘内容；“保留我的修改”把当前磁盘内容提升为新基线，再恢复本地草稿的延时保存。
- 原生 watcher 不可用时，仅对当前活动标签在窗口可见期间轮询；窗口重新聚焦时总是执行一次磁盘检查。
- 自动保存串行执行，不允许同一标签的多个写入并发；写入前使用最近确认的磁盘基线调用受保护写入，写入后回读并重新归类为干净、仍有新草稿或冲突。
- 外部删除或暂时不可读时保留内存草稿、暂停保存并显示可重试状态；文件恢复后重新读取并按同一冲突规则处理。

## 预览与主题语义

- 文件管理页和智能体工作区都向 `FileViewer` 传递当前解析后的应用主题。
- 智能体详情的 `WorkspacePanel` 虽然是独立入口，也必须使用同一个共享 CodeMirror 基础主题，不允许只依赖 GitHub 主题包的默认前景色。
- CodeMirror 主题必须与浅色、护眼、深色、午夜外观一致；应用 RGB 三元组变量只能通过 `rgb(var(--token))` 作为颜色使用。
- Markdown 默认进入渲染预览；预览区域独立滚动，正文限制可读宽度，并完整处理标题、段落、列表、链接、引用、代码、表格、分隔线与图片。
- 切换到编辑后，正文、行号、光标与选区在所有主题下可见；长行换行不会造成“只有行号”的假空白状态。

## 文件格式 IPC 合约

命令：`read_file_preview`

返回值是严格判别联合：

- `text`：包含 UTF-8 `text`，允许进入编辑与保存链路；
- `image`：包含 base64、MIME 和字节数，只读预览；支持 `png/jpg/jpeg/gif/svg/webp/bmp/ico`；
- `pdf`：包含 base64、`application/pdf` 和字节数，只读 PDF 预览；
- `binary`：不返回文件内容，只返回字节数，允许用户使用系统应用打开。

图片/PDF 上限为 10 MiB，其他候选文本上限为 2 MiB。未知扩展名不能直接视为文本，必须通过严格 UTF-8 解码；解码失败返回 `binary`。前端必须验证 IPC 完整结构，不能以强制断言或默认值掩盖字段漂移。

Orca 的 `.mmd/.mermaid`、`.csv/.tsv`、`.ipynb` 富视图是产品参考；JunQi 本轮保证这些 UTF-8 文件稳定按源码打开，不声明具备 Mermaid 图形、表格或 Notebook 富编辑能力。
