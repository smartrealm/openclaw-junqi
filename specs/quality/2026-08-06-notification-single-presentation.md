# 通知单一呈现与身份去重规格

日期：2026-08-06

## 问题

同一消息会被 Toast 和灵动岛同时呈现。另有一条 OpenClaw 助手运行可能在实时流结束和持久转录路径上使用不同通知身份，导致重复写入和重复呈现。

## 验收条件

1. `DynamicIslandSnapshot` 不含通知正文或 Toast 身份，灵动岛不订阅通知 Store。
2. 前台通知只进入 Toast；后台通知只进入系统通知。一个通知不能进入两个桌面窗口。
3. OpenClaw 持久助手键 `<runId>:assistant` 与 `cli-assistant:<runId>` 被归一为其运行键；其他助手键不做推测性转换。
4. 前端与 Rust 持久层仅按完全一致的 `dedupeKey` 去重；不得按正文、时间窗口或历史迁移删除记录。
5. 回归测试覆盖上述身份和呈现边界，静态检查、定向测试与构建通过。

## 非目标

- 不修改 OpenClaw Gateway 协议或添加 JunQi 私有 Gateway 字段。
- 不清理既有通知历史，也不为旧数据增加兼容或迁移逻辑。
