# Gateway 连接异常 UI 规格

状态：代码、自动化与本地打包完成，真机断连验收待执行

日期：2026-07-28

## 验收条件

- [x] 普通 WebSocket 断连不会显示全屏 `Promise Rejection`。
- [x] 断连仍通过共享 `chatStore` 驱动状态栏、仪表盘和 Quick Chat。
- [x] 在途请求在断连时立即以明确类型结束，不等待 RPC 超时。
- [x] 凭据切换使用同一生命周期错误契约。
- [x] 同文案的普通 Error 不会被错误策略静默忽略。
- [x] 其他未处理 Promise 错误仍显示致命诊断。
- [x] 后台队列和会话重同步 Promise 有显式终止处理。
- [x] 进程探测、运行时就绪与认证连接完成使用不同进度语义。
- [x] 带 `{{mode}}` 的文案只能由提供 `params.mode` 的类型化进度创建。
- [x] 自动和手动恢复都在认证连接后进入 `completed`，重试耗尽进入 `failed`。
- [x] 状态栏不把缺少显式状态的旧事件当作永久运行态，已连接时不显示过期自动恢复进度。
- [ ] Tauri 真机停止并恢复 Gateway 后，当前页面保留且重连 UI 自动收敛。

## 非目标

- 不改变 OpenClaw WebSocket 或 RPC 协议。
- 不把授权、配对、配置错误降级为普通断连。
- 不新增第二套连接横幅或 Toast；现有共享连接状态是唯一普通异常展示入口。
