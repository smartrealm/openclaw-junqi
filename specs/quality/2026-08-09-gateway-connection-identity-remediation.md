# Gateway 连接身份整改规格

日期：2026-08-09

## 目标

关闭 GNE-18 与 GNE-19，保证一个 `GatewayConnection` 在任何时刻只对应一个可核验的目标和一套凭据，并让
所有权限失败只通过结构化官方错误进入上层。

## 连接目标状态

1. 连接目标由 WebSocket 地址、Gateway token 和设备 token 共同确定。
2. 活动 socket 收到完全相同目标的重复 `connect` 时保持幂等，不重置重试状态、不关闭 socket。
3. 任一目标字段变化时，旧 socket 必须先失效；旧事件、旧握手和旧响应不得改变新连接。
4. 目标切换必须拒绝旧连接的待处理请求，清除 hello、运行时身份、心跳、握手期限、配对重试和自动重连计时器。
5. 新连接创建后，诊断地址、HTTP 基址、持久设备凭据和自动重连只能引用新目标。

## 权限错误边界

1. `GatewayCallbacks` 只暴露 `onAuthorizationIssue`，参数为 `GatewayAuthorizationIssue`。
2. 每个连接消费者必须明确处理结构化错误，允许只使用 `message` 展示，但不得在传输层降级为字符串回调。
3. 不保留 `onScopeError`、`isAuthError` 或其他只为旧调用方存在的包装。
4. 配对、凭据无效和权限不足继续保持不同的 `kind`，不得仅按错误文案推断。

## 设备凭据绑定

1. 端点到实例的绑定必须保持先写目标、再发布别名、最后删除源的顺序。
2. 已存在实例别名时只读取实例槽，不回退端点槽。
3. 实例凭据缺失、不可读或不支持持久化时保留对应真实状态，由配对流程决定后续操作。

## 验收

- 已连接状态切换目标时，旧 socket 被关闭且新 socket 使用新地址创建。
- 握手状态切换目标时，旧异步握手不能发送或认证。
- 同目标重复连接不创建第二个 socket。
- 全仓不存在 `onScopeError` 和 `isAuthError`。
- 已绑定实例缺少凭据时不会返回端点旧 token。
- 连接、权限分类、审批订阅和快速会话相关定向测试通过。

## 非目标

- 不修改 OpenClaw 的配对、scope 或 token 语义。
- 不增加版本门禁或方法发现 fallback。
- 不在客户端自动选择另一个 runtime 或 Gateway。
