# 原生通知投递规格

## 目标

让 JunQi Desktop 的会话回复和本地任务通知在 macOS、Windows 与 Linux 桌面环境走同一套可持久化、可点击回跳的原生通知链路。

## 约束

- 只使用当前 Tauri 版本对应的官方通知插件与项目实际 capability。
- 不使用 Electron preload、网页 `Notification` API 或浏览器开发服务器作为桌面通知实现。
- OpenClaw 会话通知只能由现有 Gateway 事件投影；客户端不得构造 OpenClaw 状态或协议字段。
- 通知的开关和勿扰必须先于任何呈现行为生效。
- 通知记录仍由现有 Rust 仓库负责持久化、去重、读取和清理。

## 验收条件

1. Rust 与前端均注册官方通知插件，所有 JunQi 窗口拥有所需 capability。
2. 启动和新手引导不主动触发通知权限；只在后台投递或用户主动测试时请求。
3. 任务通知写入成功后，前端无需等待轮询即可刷新并按设置呈现。
4. 聊天通知保留已编码的会话内部路由，点击通知记录可回到对应会话。
5. 不存在 `window.aegis.notify`、`new Notification` 或旧权限请求调用。
6. 主窗口与终端窗口显示同一持久化通知集和未读数。
