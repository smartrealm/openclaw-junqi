# 会话分组与后台活动下钻规格

## 问题

用户会话日期分组与后台活动已经在视觉上分区，但分类仍包含名称关键词推断，且后台项携带的精确 `session` 身份没有被 Cron 页面和活动中心消费。用户无法确认点击的是哪一次后台执行。

## 约束

- 以当前安装的 OpenClaw 2026.7.1 官方 Protocol、官方文档和真实 Gateway 响应为契约依据。
- 不以标题、prompt、语言、系统路径、当前用户配置或本机运行状态推断来源、任务语义或运行关联。
- 未知会话默认可见，不能因分类失败被静默隐藏。
- 任何深链都不得回退到最近活动、首条 run、当前会话或同 key 的另一 session instance。
- 前端不得新增未经官方证明的 Gateway 字段；Gateway 返回字段缺失时必须失败关闭。
- 文案覆盖简体中文、繁体中文和英文，保留上游 Agent、任务和会话显示名。

## 验收条件

1. 左侧今天、最近 7 天、最近 30 天和更早分组只接收 `conversation` 投影；archived 仍不显示。
2. 有结构化证据的 cron、子智能体、系统来源全部显示在后台活动，不依赖名称正则判断“梦境”。
3. 不匹配当前官方结构或缺少来源元数据的会话保持普通会话可见。
4. 后台活动每行至少显示已验证的标题、来源、状态和活动时间；不可用字段不显示伪值。
5. Cron 下钻的 URL 和页面状态保留 `jobId`、`sessionKey` 与已确认的 `runId`；页面仅在精确 run 匹配时选中该 run。
6. 系统活动中心消费后台活动引用，精确显示同一会话实例的详情；不存在或实例不符时显示不可用状态。
7. 子智能体下钻只打开已确认的目标会话实例，不重定向到其他会话。
8. Cron、系统和子智能体的目标页都能从 URL 刷新恢复选择；无效查询不会改变当前有效选择。
9. 分类、引用编解码、投影、目标页解析与路由交互均有行为测试；测试 fixture 明确来自已验证协议字段。
10. 相关代码通过 `pnpm lint`、相关单测、`pnpm test`、`pnpm build` 和 `git diff --check`；桌面真机验收单独记录。

## 失败关闭

- 无法把 cron session 与 `cron.runs` 的一条记录确认关联时，只打开任务并说明该次运行不可用。
- `sessions.describe` 返回的 `sessionId` 与引用不一致时，不打开 Chat 或活动详情。
- 未知分类、未知状态或缺少时间仅保留上游可用信息，不用字符串默认值掩盖。
