# Gateway 当前契约收敛整改规格

日期：2026-08-10

## 目标

删除消息身份、模型可见性和授权状态中的客户端兼容推断，使 JunQi 只消费最新版 OpenClaw 已声明的结构化字段，
并把需要运行时目录才能判断的事实留给 Gateway。

## 消息身份

1. 历史消息身份只读取 `message.__openclaw.id`。
2. 发送运行身份只读取消息顶层 `idempotencyKey`。
3. 用户消息的 `:user`、助手消息的 `:assistant` 和 CLI 助手的 `cli-assistant:` 前缀按官方持久化格式归一化。
4. 顶层 `id`、`messageId`、`clientMessageId` 和元数据中的客户端身份别名不得生成权威身份。

## 模型配置健康

1. 静态检查只判断主模型是否缺失、回退是否重复主模型，以及 `models.mode: replace` 下显式供应商目录是否完整。
2. 不从 `agents.defaults.models` 推断某个主模型或回退模型在当前运行时是否可见。
3. 模型目录、认证、别名、插件归一化与智能体作用域的最终结果只由 Gateway `models.list` 提供。
4. 删除无消费者的本地可见性复制实现、类型和专属测试。

## 授权状态

1. 授权分类只依据 `error.details.code`，或在详情码缺失时依据正式外层错误码。
2. 错误文案和 WebSocket 关闭原因不得生成配对、凭据、权限或限流状态。
3. `PAIRING_REQUIRED` 只使当前连接进入配对重试；普通策略关闭继续走连接重试策略。
4. 未知结构化代码保持未知，不映射为其他授权类型。

## 能力失败证据

1. 本地 RPC 超时必须使用带稳定错误码的专用错误类型，不返回普通字符串。
2. `INVALID_REQUEST` 只有在消息精确等于当前请求方法的官方未知方法形状时，才记录为不支持。
3. 启动期历史预热只按结构化 `UNAVAILABLE` 或本地超时类型转为后台同步。
4. 普通错误文案不得生成不支持、未授权、不可用或待核验状态。

## 全局未知方法证据

1. 原生 Gateway 客户端、数据仓、技能运行时和正式插件探测必须共用一个协议证据解析器。
2. 未知方法只接受 `INVALID_REQUEST` 与精确的 `unknown method: <当前请求方法>` 组合。
3. `METHOD_NOT_FOUND`、`UNKNOWN_METHOD`、`UNKNOWN_COMMAND`、宽松大小写、错误方法和嵌套异常均不得生成能力缺失。
4. 客户端领域层需要表达插件未安装时，使用本地 `METHOD_UNAVAILABLE`，不得冒充上游错误码。

## 配置重载规划

1. 路径重载要求只来自当前 Gateway `config.schema.lookup` 的 `reloadKind`。
2. 查询失败或缺失重载类型时失败关闭为重启。
3. 失败分类只使用稳定本地枚举，不记录或展示原始异常文本。
4. 不得按客户端版本、安装版本或固定路径表预置运行时重载规则。

## 发送失败与活动状态

1. 聊天发送检查点只能按 Gateway 错误类型或稳定错误码收敛，不得比较类名或英文消息。
2. 请求发送前的传输生命周期失败必须结束本次已创建的本地检查点，不得把未发送请求保留为运行中。
3. 请求可能已发送时仍以 Gateway 发送协调器的待核验结果为准，不得因断线推断远端失败。
4. 任务和审批 Store 不得在已知断连时制造操作错误；离线态由共享连接状态统一呈现。
5. 无上游诊断的本地兜底错误使用稳定领域码，并在 UI 边界完成多语言展示。

## Usage 数据契约

1. `usage.cost` 与 `sessions.usage` 必须在 Gateway 服务层完成完整结构校验，页面不得直接解释原始响应。
2. cost、session、aggregate、cache、latency 与模型用量结构只保留当前官方字段，不接受页面自定义别名。
3. 分析页、仪表盘和智能体设置必须复用同一类型，不得以 `any`、双重断言或元数据猜测补全模型和 Agent 身份。
4. 畸形 totals、session usage 或缺失聚合维度的响应必须整体失败关闭，不得制造空数据或部分成功。

## 验收

- 未声明消息身份别名全部失败关闭。
- 合法主模型不因供应商通配规则被静态配置页误报为不可见。
- 仅含“pairing required”文案但无结构化代码的错误不进入配对流程。
- 现有正式错误码仍映射到正确的授权类别并保留安全详情。
- 超时和未知方法均由类型化或绑定当前方法的证据驱动。
- 发送前连接失效会收敛已创建检查点，断连活动面板只显示统一离线态。
- 畸形 usage 响应无法进入数据仓，页面只消费共享的已验证结构。

## 实施状态

上述消息身份、模型配置健康、授权状态、未知方法证据、配置重载规划、发送失败与活动状态及 usage 数据契约均已按本规格收敛。定向测试、完整前端与脚本测试、
TypeScript 检查、模块边界检查和生产构建已经通过。真实最新版 Gateway 回放与 macOS、Windows、Linux
桌面验收尚未完成，不纳入自动化通过结论。
