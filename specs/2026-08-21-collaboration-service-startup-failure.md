# 协作插件服务启动失败处理规范

## 当前行为

- 协作插件 service 启动失败后，RPC 只返回通用不可用错误。
- 桌面端吞掉能力探测失败并长期展示固定百分比。
- 精确目标重启没有统一等待 Gateway 新连接和身份核验。
- 主界面直接展示英文运行时消息。

## 目标行为

### 插件边界

- schema 不匹配返回稳定错误码 `DATABASE_SCHEMA_UNSUPPORTED`。
- 结构化详情只包含实际 schema 与期望 schema，不包含路径、凭据或任意异常文本。
- 其他 service 启动失败，以及 service 未创建时的 RPC 调用，均返回 `SERVICE_START_FAILED`，内部异常只写 Gateway 日志。
- 已核对的 schema 13/14 可迁移至 schema 15：必须先创建不可覆盖的一致性 SQLite 备份，并在取得迁移写锁后确认备份期间没有其他连接写入，再在一个事务内迁移；任一校验、备份或写入失败时原库不得提交变化。
- schema 13 的删除收据和 schema 13/14 的会话命令收据只能在与当前统一收据表无冲突时复制；冲突必须失败关闭。
- 无当前消费者的历史会话变更记录只保留在迁移备份中，不得伪造为 schema 15 的活跃状态。
- 任何影响协作 RPC 返回形状、错误码或启动状态语义的插件变更必须提升插件版本，并重新生成固定
  归档及前端、Rust 两端 metadata。相同版本的旧插件不得被判定为当前固定包。

### 生命周期

- 安装事务发出精确目标重启后，桌面端必须通过唯一 Gateway 生命周期协调器等待新连接。
- 协调器返回失败时，操作结束为错误，不得继续健康确认。
- 新连接身份未通过核验时不得确认插件健康。

### 界面

- 没有真实进度事件时使用不确定进度，不显示百分比。
- 结构化启动失败结束等待并显示本地化主提示。
- 技术详情可显示已脱敏诊断、实际 schema 与期望 schema。
- 任意未结构化运行时错误和阻断原因不得作为主提示直接显示；主提示必须使用本地化的稳定状态。
- 可恢复安装事务显示回滚入口；回滚必须保留既有确认步骤。
- 协作办公室使用相同本地化错误映射，并提供打开协作修复入口。
- 亮色、暗色和护眼主题均只使用现有语义主题 token。

## 验收条件

1. 已知结构的 schema 13 数据库会在备份成功后迁移至 schema 15；映射后的收据可读取，旧会话变更记录可在备份中恢复。
2. schema 13/14 的未知结构、收据冲突、无效墓碑或备份失败均不提交迁移，保留明确错误。
3. 能力探测失败不会被转换为无诊断的 `null`。
4. 重启请求成功后会调用统一连接恢复入口并检查结果。
5. 没有 Gateway 进度事件时 DOM 中不存在伪造的 58% 或 82%。
6. 中文、英文和繁体中文都有对应主提示，运行时英文消息只出现在技术详情中。
7. 协作办公室不再把 `JunQi collaboration service is not running` 作为用户主提示。
8. 简体中文、繁体中文和英文均包含协作设置界面使用的全部翻译键。
9. 旧 `0.5.0` 协作插件安装后，当前固定包被识别为更新；更新后的 service 缺失响应包含
   `SERVICE_START_FAILED`，而非未结构化英文文本。
10. 协作读取不会请求 `operator.admin`；管理权限升级只由对应的 OpenClaw 管理操作触发。
