# 目标运行环境 Node.js 决策规格

## 范围

本规格只约束 Native 安装流程中的 Node.js 与 npm 复用判断、进度呈现和安装前复核。不定义新的 OpenClaw 运行时能力，也不改变 Native 与 Docker 的用户选择边界。

## 事实来源

- Node.js 版本范围来自当前已安装 OpenClaw 包或当前目标 npm 包的 `engines.node`。
- Node.js 与 npm 路径、版本和来源来自目标机器的 Runtime 探测。
- 开发机的路径、版本、登录用户和构建环境不进入任何运行时决策。

## 验收条件

1. 当前所选 Runtime 存在满足目标 `engines.node` 范围且含自带 npm 的 Node.js 时，首次检查直接完成 Node/npm 步骤，不进入 Node 安装操作。
2. 当前所选 Runtime 只检测到不满足范围的 Node.js 时，界面与进度事件同时显示检测到的版本和目标范围；不得显示为“未检测到 Node.js”。
3. 没有可执行 Node.js 时，界面显示目标范围，不伪造已检测版本或路径。
4. Node 安装或修复入口在下载、系统安装或覆盖前重新检查完整 Node/npm 契约；已有兼容运行时则直接返回。
5. Node 必须与其自带 npm 成对使用；不得从另一 PATH 条目借用 npm。
6. 目标包版本范围无法取得时，不得以开发机版本、硬编码范围或猜测性成功继续写入安装；实际安装边界必须重新核对或失败。
7. 简体中文、繁体中文和英文的相同状态均可本地化，动态版本和范围只来自当前探测结果。
