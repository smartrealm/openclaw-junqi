# 钉钉 DWS 工作流扩展规格

## 范围

按照写入可靠性、只读聚合、会议、听记、知识、汇报、草稿通信、实时事件和敏感业务域的顺序扩展 `junqi-dingtalk`。每一阶段只能使用目标 DWS 叶子 schema 已证明存在的固定白名单工具。

## 第一阶段验收

- 写工具必须使用 DWS 官方已内置权威读回的 Shortcut，或在插件中执行固定的 schema 核验读取，且不得自动重放原写命令。
- 创建和更新日程、创建和更新待办、完成和重开待办、按关键词同意审批必须要求 DWS Shortcut 返回稳定 ID 与 `verified=true`。
- 发起审批必须从官方原子响应中提取稳定实例 ID，并用同一 ID 读取详情。
- 日报周报提交必须先读取模板和字段定义，提交后从官方响应提取稳定 reportId，并用同一 ID 读取日志详情；正式详情契约不能证明全部字段和接收人时只能进入 `succeeded_unverified`。
- 聊天发送只允许 DWS 当前用户原子叶子、一个稳定群 ID 或 openDingTalkId、文本正文和必填的操作级幂等键。自然语言目标、Bot、Webhook、批量、提及、附件和媒体参数必须在调用前失败关闭。
- 聊天发送审批必须完整展示精确 Profile、稳定目标、正文和幂等键。异步回执必须先用正式任务状态查询取得消息与会话 ID，再通过 `chat +messages-mget` 读取同一消息；只有 `messagesComplete=true`、请求数、命中数、失败数、缺失列表、消息 ID 和群会话 ID 全部一致时，才可证明同一消息存在。仍在处理或任一完整性字段不一致时进入 `unknown`，不得重发。
- 聊天精确 ID 读回成功只能进入 `succeeded_unverified`，直到正式读取契约能够证明完整正文和接收人后置条件。
- 审批拒绝和撤销必须从已核验输入取得实例 ID 并读取同一对象，但在缺少正式终态契约时不得进入 `verified`。
- 读回身份与预期 ID 不一致时必须进入 `unknown`，不得报告成功。
- 更新、完成、重开和取消类核验 Shortcut 的回执资源 ID 必须与请求中的稳定资源 ID 完全一致；不能只凭 `verified=true` 接受其他对象的回执。
- 读回成功且能证明预期后置条件时进入 `verified`；只能证明对象存在时进入 `succeeded_unverified`。
- 写入后读回失败、取消、超时或 schema 漂移时进入 `unknown`，并提供稳定错误码，不自动重试。
- `destructive` 与 `write` 共用副作用围栏和核验状态；取消、超时、输出超限或进程结果丢失时不得按普通读取失败处理。
- 活动记录只能保存工具名、schema 摘要、核验状态、核验工具和资源引用，不保存业务正文。
- 只读工具仍可进入 `succeeded`，不得错误显示为写入已核验。

## 后续阶段共同验收

- 新工具必须包含固定名称、官方 canonical path、CLI path、effect、risk、confirmation 和 idempotency 契约。
- 所有已注册业务工具和事件消费契约都必须由当前叶子 Schema 明确声明 `availability=available`；字段缺失或值为 `unavailable` 时失败关闭，不得注册或启动对应能力。
- 每次调用前都由目标 DWS 运行时叶子 schema 核验，参数只从 schema 白名单构造。
- 契约核验必须读取完整叶子 Schema，并把 `cli_required`、默认值、接口类型、枚举、格式、`anyOf` 和跨参数约束纳入摘要。向 Agent 返回时只能保留调用所需参数和约束，不得暴露字段来源审计树。
- 输入必须在 DWS 启动前验证 `required`、`cli_required`、CLI 类型、枚举、已知格式，以及 `mutually_exclusive`、`require_one_of`、`require_together`。DWS 约束中的隐藏兼容参数只能投影到当前可调用参数面；过滤后无法满足的至少一项或成组提供约束必须失败关闭。
- `interface_type=array` 且 CLI 类型为 `string` 的枚举参数必须按正式 CSV 语义逐成员核验，不能把整个 CSV 当作单个枚举值，也不能让非法成员通过。
- `required_when` 是上游自然语言契约，不得由 JunQi 通用解析器猜测条件语法。当前注册面只有聊天富媒体参数携带该字段，而这些参数已被当前用户文本窄发送策略拒绝；未来开放任何条件参数前必须增加该叶子的显式验证策略。
- OpenClaw 实际业务只读工具和目标验收中的业务读取都不能只依赖进程退出码；必须同时取得统一结果信封的 `ok=true`、`outcome=success` 和显式 `data` 字段。零退出的失败、等待或畸形信封必须以稳定错误失败关闭，且不得保留原始错误或业务载荷。长驻事件消费按正式 ready 与扁平 NDJSON 契约独立验收，不套用一次性 JSON 信封。
- DWS Schema 中的字符串列表参数必须按 CLI 的 CSV 语义传递；必填空数组、非字符串成员和未知参数必须在启动 DWS 前失败关闭，不得把 JSON 数组文本当作一个列表成员。
- DWS Schema 声明为 `string` 的标量参数必须拒绝对象、数组、布尔值和数字，不得隐式 JSON 序列化后交给 CLI。
- 写工具必须经过 OpenClaw `before_tool_call` 审批，并有写后权威重读或明确的待核验语义。
- 副作用工具必须在请求审批前核验精确 Profile、当前 DWS 叶子 Schema、全部参数类型、审批摘要策略和写后核验策略；任一项失败时不得展示可批准入口或启动业务命令。
- 13 个副作用工具的审批摘要必须展示目标和实质改动，并以完整参数对象的 SHA-256 绑定该次调用。摘要必须不超过 OpenClaw 正式 512 字符上限；日报正文、审批表单值、完整审批请求和日程描述只展示长度与整组参数指纹，不得复制到通知正文。
- 每个注册的 `write` 或 `destructive` 工具都必须出现在显式核验策略注册表中；缺少策略的副作用工具必须在读取目标 Schema 和启动 DWS 前失败关闭，不得先执行后再归类为未知。
- 非幂等操作在未知结果时禁止自动重试。
- 复合工作流不得伪造事务；部分成功时列出已完成步骤，后续由权威读取对账。
- 插件工作流必须通过 OpenClaw 正式 Skill 扩展点交付，只能引用插件已注册的固定工具，不得指导 Agent 运行任意 DWS 命令。
- Skill 路径必须位于插件根目录内，`SKILL.md` 必须是普通文件，frontmatter 必须包含与目录一致的非空名称和不超过 1024 字符的描述；插件校验失败时不得打包。
- 工作流首次使用每个业务工具前必须读取该工具的当前 Schema，全程绑定同一精确 Profile，并要求业务目标唯一匹配。
- 日程、待办、审批、文档、纪要、日报、消息和邮件均绑定精确 `<corpId>:<userId>` profile。
- 敏感业务正文、附件、合同和个人信息不进入 JunQi 本地活动持久化、日志或测试快照。

## 阶段能力

1. 写入核验：以 7 个 DWS 核验 Shortcut、发起审批读回及两个待核验审批动作构成写入面，并修复桌面活动状态。
2. 每日助理：只读聚合当日日程、逾期未完成待办、今日到期待办和待审批；各来源独立报告失败或不完整，不创建并行任务语义。
3. 会议闭环：查人、查忙闲、查会议室、建会、邀请、改期、变更参会人、读取会议详情、经明确确认取消并验证日程不存在，再按标题或时间唯一搜索关联纪要和后续待办。
4. AI 听记：只有明确请求最新听记时使用 latest；指定会议必须搜索并唯一定位。逐字稿读取必须传入同一稳定 taskUuid，禁止自动选择、关键词选择、续页游标和单页模式，且只有在结果证明同一 taskUuid、`complete=true` 及页数与段落计数一致后，才能经人工确认精确批次转换为待办或日报周报草稿。
5. 文档知识：文档、知识库和搜索只读能力优先。
6. 日报周报：读取、生成草稿、核对模板字段与接收人、人工确认提交，并按 reportId 写后核验。
7. 消息邮件：草稿与发送分离。当前用户单目标文本消息可在完整人工核对后单独审批发送，并依次查询异步状态和精确消息 ID；Bot、Webhook、批量、富媒体和邮件发送保持关闭。
8. 实时事件：插件服务拥有事件进程、身份、重连、去重、有界缓冲和 Gateway 生命周期。
9. 高敏域：AI 表格、合同、招聘和目标管理按读写风险逐工具开放；HRbrain 当前正式叶子均不可用，不注册工具，也不显示为可用能力。

## 事件运行时验收

- 只有 OpenClaw 完整运行模式可以注册事件服务，发现和工具发现模式不得启动子进程。
- 未配置事件组时保持关闭；配置事件组时必须绑定精确 `<corpId>:<userId>`，最多 8 个事件组。
- 只接受 DWS 官方 27 个个人 EventKey，同一进程不得混合不同目标类别；需要用户、开放用户 ID、群或待办角色的事件必须满足正式参数互斥规则。
- 创建订阅前必须核验目标 DWS `event.consume` 的 canonical path、安全元数据和运行所需参数。
- 单事件 ready 必须匹配所请求 EventKey，多事件 ready 的数量必须匹配所请求事件数；不得用延时猜测启动成功。
- stdout 必须按有界 NDJSON 行解析；单行 JSON 异常不得吞掉后续行，超长行必须进入协议失败。
- 事件按正式稳定 ID 去重；VoIP 优先使用 `biz_id`，其他事件使用 `event_id`。无稳定 ID 时不猜测去重键。
- 插件调用 `gatewayEvents.emit` 时只能使用符合 OpenClaw 正式正则的局部名 `events_changed`；线上的完整名称必须由 OpenClaw 生成为 `plugin.junqi-dingtalk.events_changed`，不得由插件自行传入带点名称。
- Gateway 事件通知只能包含 revision、事件类型、运行代际 UUID 和完整规范化事件配置的 SHA-256；完整业务 payload 只存在于有界进程内存和内部 Agent 工具结果。通知发送失败进入服务健康失败，但不能把已接受的 DWS 业务行误记为协议坏行或增加拒绝计数。
- 事件快照必须分别报告配置事件组数量、仍存活的 consumer 数量和已通过 ready 核验的 consumer 数量，不得仅用配置数量暗示运行正常。
- 桌面重读必须使用插件注册的 `junqi.dingtalk.events.snapshot` Gateway 方法，显式要求 `operator.read` 和已认证 Profile，不得为只读状态借用需要 `operator.write` 的 `tools.invoke`。请求只接受 `afterSequence` 和 1 至 20 的 `limit`；返回事件必须全部晚于请求游标，游标早于最新序号时返回末项必须等于最新序号。响应只包含运行状态、计数、契约摘要与事件序号、时间、类型，不得包含事件 ID 或业务 payload。
- 停止时必须先关闭 stdin；超时后仅使用 DWS 正式支持的 SIGTERM，不得使用 `kill -9`。清理无法确认时报告失败，不能伪报已停止。
- consumer 意外退出进入 `degraded` 并报告服务健康失败，不自动换订阅 ID 或并发重启。

## 事件配置验收

- 钉钉接入工作区必须通过正式 `config.get` 信封读取事件配置；配置存在时没有 `hash` 必须失败关闭。
- 桌面端只允许修改 `eventProfile`、`eventSubscriptions` 和 `eventBufferSize`，不得覆盖插件路径、Agent 授权或其他插件配置。
- 订阅数组写入必须把 `plugins.entries.junqi-dingtalk.config.eventSubscriptions` 放入精确 `replacePaths`，并把最新 `hash` 原样作为 `baseHash`。
- 写入回执后必须再次执行 `config.get`，只有三个事件字段与请求完全一致才可进入重启；不一致时不得报告成功。
- 启用配置必须选择运行时返回且状态为 `active` 的精确 Profile。事件类型、目标类别、成员、群和待办角色使用与插件 manifest 相同的闭集。
- 没有变化时不得写配置或重启。远端或未授权桌面修改的 Gateway 只允许读取，不显示可执行的保存语义。
- 写入确认后只能通过共享 Gateway 生命周期入口重启；运行目标在写入期间变化时保留“配置已写入但未应用”状态，不得重启新的目标。
- 重启后必须对同一运行目标再次读取配置。重启或重读失败时保留已确认写入的配置，并明确显示运行时应用尚未完成。
- 桌面端只能消费精确的 `plugin.junqi-dingtalk.events_changed` 顶层事件，载荷必须闭合为正安全整数 revision、有界非空 eventType、版本 4 UUID 运行代际和小写 SHA-256 配置摘要。保留事件载荷无效时失败关闭且不得落入通用聊天处理。
- 最近通知必须绑定接收时已核验的 Gateway connectionId；连接变化或事件配置未确认启用时不得显示旧通知。界面只能表达“有新事件可读取”，不能从通知推断事件正文、订阅健康或任何业务动作终态。
- 事件配置已启用时，桌面必须在进入运行时页面和收到新 revision 后通过当前连接围栏重读操作员快照。配置读取结果必须绑定产生它的 connectionId；新连接不得沿用旧连接配置发起快照读取。桌面必须按与插件相同的规范序列化重算完整配置 SHA-256，并在发布前核对 connectionId、运行代际、配置摘要、已保存 Profile、订阅组数量、EventKey 集合和通知的最低 revision；同一运行代际的重复、倒退 revision 或摘要漂移必须丢弃，新代际才允许序号从一重新开始。晚到的旧连接、旧配置、旧代际、旧 revision 或旧请求结果不得覆盖当前状态。自动重读失败必须在事件区域就地显示并允许手动重试，不能伪造空快照或运行正常。

## 隔离真实 Gateway 基线验收

- 必须只安装仓库固定钉钉归档，并在安装前核对资源元数据、生成元数据、归档摘要和包目录归档逐字节一致。
- 不得挂载或读取宿主 OpenClaw 配置、状态、工作区和凭据；安装容器只能挂载独立状态卷与只读归档，运行容器只能挂载独立状态卷。
- 安装期使用专用网络，运行期必须切换到无出口内网、非默认动态端口且不发布宿主端口。Gateway 令牌只能通过运行容器环境变量传入，不能出现在参数、证据或日志中。
- 插件配置只能包含测试 Agent 白名单，不得配置 `dwsPath`、`eventProfile` 或 `eventSubscriptions`。运行进程列表出现 DWS 子进程必须失败。
- `junqi.dingtalk.events.snapshot` 必须通过 OpenClaw 正式 Gateway 调用入口显式申请 scopes，且使用只读共享状态模式。仅申请 `operator.read` 必须返回关闭态投影；仅申请 `operator.write` 必须返回 `FORBIDDEN`，并携带 `MISSING_SCOPE`、`missingScope=operator.read` 和唯一 `requiredScopes=operator.read`。不得使用普通管理 CLI 的宽权限默认值替代这组正反向证明。
- 动态通过条件包括归档真实安装、OpenClaw 配置校验、插件检查、上述最小 scope 正反例、关闭态闭合投影，以及 Gateway 重启后配置摘要不变而运行代际 UUID 改变。
- 该基线使用固定最低兼容 OpenClaw 运行时，只证明该版本的无租户关闭态装载与 scope 链路。最新版主线源码审查、认证 Profile 不可用拒绝、目标 DWS、业务读写、事件订阅和线上前缀广播必须分别验收；无认证身份同步信息的令牌客户端不能证明 Profile 门禁。
- Docker 预检失败时必须保留失败证据并完成所有权围栏清理；未进入插件安装不得描述为插件加载失败或动态验收通过。

## 隔离 Gateway 插件调用链验收

- 调用链模式必须复用同一固定归档、只读根文件系统、独立状态卷、无出口运行网络、动态端口、环境变量令牌和所有权清理边界，不得读取宿主 OpenClaw 或 DWS 配置。
- 只允许在运行容器额外挂载一个仓库维护的只读 DWS 测试执行器；挂载源、目标和只读属性必须逐项核验，出现额外挂载或可写挂载立即失败。
- 测试执行器只能接受 `contact.get_current_user_profile` 的精确 Schema 命令和同一 Profile 的 `contact user get-self` 精确业务命令；其他命令、参数、Profile 或格式必须非零退出。该执行器不得成为插件产品 fallback，也不得进入固定插件归档。
- 必须先以 `operator.write` 调用正式 `sessions.create` 建立不启动 Agent run 的隔离 Session，再以 `operator.read` 调用 `tools.effective`；只有实际工具清单中存在唯一、未被 Session 拒绝、归属于 `junqi-dingtalk` 的当前用户工具才可继续。
- 业务读取必须以 `operator.write` 调用正式 `tools.invoke`，核对外层 Gateway 传输、插件来源、工具名称、Schema 摘要、统一成功信封、闭合测试 payload 和文本详情一致性。调用后不得残留 DWS 子进程。
- 持久证据只能保留工具名、插件归属、Schema 摘要和结构性布尔结论，不得保留 Profile 或业务 payload。
- 该验收只证明固定 OpenClaw 基线中的 Session、最终工具策略、插件、runner、子进程和结果投影链路，不证明正式 DWS 二进制、认证 Profile、钉钉网络、目标租户权限或真实业务数据。

## 目标 Gateway 当前用户读取验收

- 命令必须连接用户显式指定的目标 Gateway，并从用户显式指定的 OpenClaw `package.json` 解析正式 `openclaw/plugin-sdk/gateway-runtime` 导出；不得读取宿主 PATH、猜测安装目录、调用普通管理 CLI 的宽权限默认值，或复制 Gateway WebSocket 协议。
- Gateway URL 只允许根路径的 `ws` 或 `wss` 地址，不接受 URL 用户名、密码、查询参数或片段。Gateway 令牌只允许通过 `OPENCLAW_GATEWAY_TOKEN` 环境变量进入正式客户端，不得出现在命令参数、成功证据或失败输出中。

## 目标租户事件消费验收

- 必须显式传入 DWS 绝对路径、精确 Profile、一个已审阅 EventKey、5 至 300 秒等待时间和固定订阅确认串。用户、开放钉钉 ID、群和待办角色参数必须继续通过正式事件类别闭集校验。
- 启动前必须核验当前 `event.consume` 叶子 Schema；只有精确 ready marker 才能把消费者视为就绪。ready 后没有真实事件必须返回 `ready_no_event`，不得算作通过。
- DWS `--flatten` 输出的 `type` 必须是非空字符串并属于当前 consumer 请求的 EventKey。缺失类型或跨订阅类型必须增加拒绝计数、进入降级状态，且不得进入缓存、去重集合或 Gateway 通知。
- 通过条件必须同时具备一个就绪 consumer、无拒绝和丢弃、至少一个内存事件，以及与该事件序号和类型一致的正式局部失效通知。任何不一致都返回 `invalid_notice`。
- 验收结束必须关闭 stdin 并等待进程干净退出。停止超时优先返回 `stop_unverified`，不得自动重建、重试或推断远端订阅已经清理。
- 输出只保留契约计数与摘要、ready 数、事件与通知计数、序号、事件类型、拒绝数、丢弃数和脱敏错误；不得保留 Profile、订阅 ID、事件 ID 或业务 payload。
- 直接验收成功只证明插件内 DWS 进程、ready、事件接收、类型约束、内存投影、局部通知和进程停止。OpenClaw Gateway 前缀与广播、桌面连接围栏、快照重读、Gateway 重启、断线和远端退订仍需目标环境分别验证。

## 目标租户日程写入验收

- 必须显式传入 DWS 绝对路径、精确 Profile、唯一合成标题、不同的新标题、完整起止时间和固定写入确认串。写入验收编排自身必须在任何副作用前以同一 DWS 和同一 Profile 执行 `core` 五项只读预检，不得依赖维护者声称之前已经单独执行。
- 核心只读预检必须继续全部五项以形成完整脱敏失败矩阵；任一项失败时必须返回 `failed_before_write`、`failedStage=readonly_preflight` 和零已完成写入步骤，不得进入创建。
- 写入前必须一次性核验创建、更新和取消三个当前叶子 Schema，并用各自 Schema 校验全部参数；任一契约失败时不得执行任何写入。
- 创建必须取得稳定 eventId 与 `verified=true`；更新和取消必须使用该 eventId，并要求各自回执返回同一 eventId 与 `verified=true`。
- 正常路径只允许依次执行创建、改名和取消，成功后不保留测试日程。该入口不能接受任意命令、已有 eventId 或额外业务参数。
- 创建结果未知时必须按唯一标题人工检查，不得重试创建。已知 eventId 后更新或取消结果未知时必须停止后续写入，返回该 eventId 供人工检查，不得自动重试或自动追加清理。
- 输出只保留契约计数、已完成步骤、失败阶段、稳定资源 ID、核验状态和脱敏错误，不保留 Profile、标题、时间或日程正文。
- 成功只证明目标 DWS 的日程 Shortcut 创建、更新、读回与删除链路，不代替 OpenClaw Gateway 审批、Agent 授权、桌面状态投影、事件或其他业务域验收。

## 目标租户待办写入验收

- 必须显式传入 DWS 绝对路径、精确 Profile、执行人 userId、唯一合成标题、不同的新标题和固定写入确认串。写入验收编排自身必须在任何副作用前以同一 DWS 和同一 Profile 执行 `core` 五项只读预检，不得把独立命令的历史结果当作当前资格。
- 核心只读预检必须继续全部五项以形成完整脱敏失败矩阵；任一项失败时必须返回 `failed_before_write`、`failedStage=readonly_preflight` 和零已完成写入步骤，不得进入创建。
- 执行人必须与 Profile 中的 userId 完全一致；该验收不得把测试待办分配给其他成员。
- 写入前必须一次性核验创建、更新、完成和重开四个当前叶子 Schema，并用各自 Schema 校验全部参数；任一契约失败时不得执行任何写入。
- 创建必须取得稳定 taskId 与 `verified=true`；更新、首次完成、重开和最终完成必须使用该 taskId，并要求各自回执返回同一 taskId 与 `verified=true`。
- 正常路径只允许依次执行创建、改名、完成、重开和再次完成。成功终态是一条已完成的合成待办记录，不得宣称已从租户删除。
- 创建结果未知时必须按唯一标题人工检查，不得重试创建。已知 taskId 后任一步未知时必须停止后续写入，返回该 taskId 供人工检查，不得自动重试或自动改变状态。
- 输出只保留契约计数、已完成步骤、失败阶段、稳定资源 ID、核验状态和脱敏错误，不保留 Profile、执行人、标题或待办正文。
- 成功只证明目标 DWS 的待办创建、更新、完成与重开 Shortcut 链路，不代替 OpenClaw Gateway 审批、Agent 授权、桌面状态投影、事件或其他业务域验收。

## 目标租户审批预检

- 必须显式传入 DWS 绝对路径、精确 Profile、processCode、部门 ID 和表单值。当前只接受 DWS 正式简单模式，表单值必须是非空的“字段名到字符串”JSON 对象，不接受完整请求或自定义任意命令。
- 读取租户数据前必须一次性核验表单 Schema、流程预测、发起审批、审批详情和撤销审批五个当前叶子契约，并以各自 Schema 校验计划参数；任一契约失败时不得调用任何业务命令。
- 只允许依次读取精确表单 Schema 和使用同一 processCode、部门 ID、表单值执行流程预测，不得发起、同意、拒绝或撤销审批。
- 表单与流程预测都必须返回统一成功信封；任一信封失败、等待或畸形时立即停止后续读取，并保留零写入结论。
- 输出只保留契约计数、读取计数、完成阶段、是否需要人工复核和脱敏错误，不保留 Profile、processCode、表单值、审批路径或任何业务 payload。
- `ready_for_manual_review` 只证明目标 Profile 能读取该表单并用给定字段到达正式预测接口。实际发起前仍必须通过已审查的 OpenClaw 工具人工核对表单字段、预测路径、自选审批节点和接收人。
- DWS 正式撤销契约目前不能证明通用终态，且不同审批模板不能假定可安全自审批或自动清理，因此不得提供通用自动创建、审批和撤销验收链路。

## 目标租户日报模板预检

- 必须显式传入 DWS 绝对路径、精确 Profile、精确模板名、内容 JSON 数组和逗号分隔接收人。不得接受内容文件、标准输入、发送到聊天或任意请求模式。
- 读取租户数据前必须一次性核验模板搜索、模板定义、日志提交和日志详情四个当前叶子契约，并以各自 Schema 校验计划参数；任一契约失败时不得调用任何业务命令。
- 内容数组必须非空，每项必须提供非空 `key`、整数 `sort`、字符串 `content`、正式字段 `type` 和与字段类型匹配的 `contentType`；接收人不得为空、包含空成员或重复。
- 只允许先执行模板名称搜索，严格检查统一结果信封、数量、稳定 templateId 和重复身份，再要求搜索结果中恰好一个名称完全相同的模板。零个或多个精确匹配都必须停止，不能读取定义或猜测选择。
- 唯一匹配后只读取该精确名称的模板定义，并用真实 templateId 再次校验计划提交参数；不得提交日报，也不得用任意内容执行探测。
- 模板定义必须返回统一成功信封；零退出的失败、等待或畸形信封不能进入人工复核就绪状态。
- 输出只保留契约计数、读取计数、完成阶段、是否需要人工复核和脱敏错误，不保留 Profile、模板名、templateId、内容、接收人或任何业务 payload。
- `ready_for_manual_review` 只证明目标 Profile 能唯一定位模板、读取模板定义且计划参数符合当前叶子 Schema。由于模板定义叶子没有正式结果 schema，实际提交前仍必须通过已审查的 OpenClaw 工具人工逐字段核对 key、sort、type、内容和接收人。
- 当前正式契约没有可安全删除已提交日报的清理链路，因此不得提供通用自动提交验收；目标租户真实提交必须作为单独审批的可留痕操作执行。
- 正式日报写工具只接受 OpenClaw 参数中的内联 `contents`，在审批前执行 1 MiB UTF-8 上限检查，并转换为 DWS 官方 `--contents -` 标准输入模式；不得接受 Gateway 主机上的任意 `contents-file` 路径，也不得把正文放入子进程参数。

## 明确不做

- 不提供任意 DWS 命令执行器。
- 不根据工具名、模型记忆或最新版仓库推断目标运行时已支持某命令。
- 不由 JunQi 定义新的 OpenClaw Agent、Task、Transcript、审批或事件协议。
- 不把 DWS 官方原始 Skill 直接打包进 JunQi，因为其任意命令面超出当前固定工具白名单。
- 不在没有权威结果字段时把详情读取成功解释为业务动作终态成功。
