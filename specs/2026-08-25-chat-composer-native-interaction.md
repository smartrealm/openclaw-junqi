# 会话输入区原生交互规格

日期：2026-08-25

## 目标

JunQi 会话输入区以一个稳定主操作位呈现 OpenClaw 的真实发送与中止状态。任何按钮标签都必须来自当前输入状态和 Gateway 已返回的会话队列模式，不得模拟暂停、恢复、成功或本地队列。

## 状态与行为

### 空闲会话

- 无文本且无附件：显示不可用的发送按钮。
- 有文本或附件：显示可用的发送按钮。
- 点击发送或按 Enter 调用 `chat.send`，不强制附加 `queueMode`。
- Shift+Enter 插入换行；输入法组合期间的 Enter 不发送。

### 活动运行

- 无文本且无附件：同一主操作位显示停止按钮。
- 有文本或附件：同一主操作位显示发送类操作，不再同时展示独立的发送、转向和停止按钮。
- 有效模式为 `steer`：显示转向动作，普通发送仍省略显式覆盖，由 Gateway 使用当前有效模式。
- 有效模式为 `followup` 或 `collect`：显示加入后续队列动作。
- 有效模式为 `interrupt`：显示中断并发送动作。
- 有效模式未知：显示通用发送动作，不猜测执行模式。
- Ctrl+Enter 或 Command+Enter 在活动运行且有内容时明确调用 `chat.send` 并携带 `queueMode: "steer"`。
- Escape 在无菜单和无输入法组合时停止当前运行。

### 停止

- 有精确 `runId` 时调用 `sessions.abort` 并携带该标识，不清理其他待发内容。
- 无精确 `runId` 且目标是明确的非全局会话时，按会话键中止并设置 `clearQueued: true`。
- Stop 不清空草稿，不删除会话，不删除 transcript，不展示为暂停，也不提供恢复同一次运行的动作。
- 中止后的部分输出只按 OpenClaw 历史和事件重新核验。

### 历史输入

- 上下方向键继续浏览本会话用户输入历史。
- Escape 不再复制最近用户消息。
- 已发送消息的回退或分支继续使用现有 `sessions.rewind` 和 `sessions.fork`，不直接修改 OpenClaw transcript。

### 已发送用户消息操作

- 已持久化消息不得在本地原地编辑；“编辑并重新发送”必须调用 `sessions.rewind`，仅在 Gateway 成功后用 `editorText` 和 `editorAttachments` 替换输入框并刷新历史。
- 编辑入口必须明确提示活动分支将回退、该消息会恢复到输入框、既有记录仍保留且文件和工具副作用不会撤销，不能把结构变更语义藏在无文字的回转箭头中。
- `sessions.fork` 属于低频会话结构操作，应使用带可见文字的菜单项，不与多 Agent 协作入口并排形成相似图标。
- 复制是无副作用的直接操作；多 Agent 协作保持独立动作和原有能力门禁。
- 断线、活动运行、历史加载或另一项会话结构操作进行期间，编辑和分叉入口必须禁用并提供具体原因。

## 视觉与可访问性

- 主操作位尺寸和位置稳定，不因运行状态增加并排主按钮。
- 使用既有 `aegis-*` 主题 token、现有输入容器、圆角、焦点环和动效时长。
- 每个动作具备本地化的 `title` 和 `aria-label`。
- 禁用、加载、断线和历史加载期间不得接受发送。
- 窄窗口下输入框保持可用宽度，主操作始终可达。
- 动效仅改变图标、颜色、透明度或变换，并遵守减少动态效果偏好。
- 已发送消息的会话分叉与多 Agent 协作必须使用不同图标；协作入口复用紧凑消息操作按钮，通过本地化 tooltip、`title` 和 `aria-label` 提供完整名称。
- 后台确认消息身份时不渲染协作入口或加载占位；只有待启动或已有运行可查看时才显示成员图标，不能挤压消息正文和时间操作行。
- 草稿高频更新只能通知实际消费草稿的输入组件；应用根、会话页签、命令面板和其他无关页面不得订阅 ChatStore 全量状态。
- 助手流式内容更新不得通过完整消息数组订阅持续重绘输入框；历史输入仅在用户触发上下方向键时读取当前用户消息。

## 协议约束

- 所有消息发送统一调用 `chat.send`。
- `queueMode` 只接受官方四个值：`steer`、`followup`、`collect`、`interrupt`。
- 显式 `steer` 不携带 `expectedLeafEntryId`；其他发送继续使用已有活动叶节点并发围栏。
- 不以 `hello-ok.features.methods`、安装版本、本机日志或本地配置推断能力。
- 结构化 Gateway 拒绝原样进入现有错误处理，不降级到废弃方法或本地重发。

## 验收条件

1. 任一状态最多显示一个发送或停止主操作。
2. 主操作状态矩阵具有行为测试，修复前能复现多按钮或错误动作选择。
3. 会话投影保留合法的 `queueMode` 和 `effectiveQueueMode`，未知值保持未知。
4. 显式转向通过 `chat.send queueMode: "steer"`，仓库中不存在运行时 `sessions.steer` 调用。
5. Enter、Shift+Enter、修饰键 Enter、Escape 和输入法组合均有回归覆盖。
6. 精确运行停止与键级停止的队列处理均有回归覆盖。
7. 相关旧客户端、专属测试和过时文档结论被删除或更新。
8. 定向测试、完整前端测试、lint、build 和 `git diff --check` 通过。
9. 真实 WebView 未覆盖的主题、窗口和连续交互状态在项目状态中明确标记。
10. 组件回归证明多 Agent 协作入口仅在可操作时显示成员图标，不复用会话分叉图标，后台确认态不产生任何标记。
11. 草稿更新和助手流式内容更新前后，应用运行态与输入框非文本依赖的订阅投影保持浅相等。
12. 已发送用户消息提供可理解的“编辑并重新发送”入口，实际仍调用 `sessions.rewind`；布局回归证明操作层级不会把 fork 或协作混作直接编辑，确认文案准确说明活动分支、既有记录和工具副作用边界。
