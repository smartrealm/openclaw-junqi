# OpenClaw 2026.8.1 桌面兼容规格

日期：2026-09-01

## 范围

本规格覆盖内置插件的 2026.8.1 编译与验证基线，以及官方结构化提问在 JunQi 会话输入区的可视化交互。其他 2.0 能力只有在仓库现有实现与正式 Gateway 契约已经对应时做回归核对，不扩展为猜测性功能。

## 插件兼容验收

1. 协作插件与钉钉插件以 OpenClaw `2026.8.1` 作为开发依赖和构建元数据来源。
2. 两个插件继续使用官方聚焦 SDK subpath，不导入被 2.0 删除的宽入口。
3. 内置插件只声明当前已编译和验证的 `2026.8.1` SDK 与 Gateway 下限，不保留旧插件 API 双轨。
4. 真实协作验证使用官方 `2026.8.1` 容器 tag 与不可变 manifest digest，不保留旧镜像 fallback。
5. 固定包内容变化时升级对应插件版本并重建资源元数据。

## 结构化提问验收

1. 主 Gateway 连接按官方客户端契约申请 `operator.questions`；提问列表、事件、普通回答、密钥回答和跳过都复用该连接，不创建问题专属并行连接，也不为回答申请 `operator.admin`。
2. 连接建立或恢复后调用 `question.list`，只投影协议合法且仍为 `pending` 的记录。
3. `question.requested` 新增或更新问题，`question.resolved` 按 id 原子移除问题；晚到事件不得跨 Gateway 连接身份污染当前投影。
4. 只在当前 Session 显示其问题；没有 Session 绑定的问题保留为全局待答请求，并明确显示来源未知，不伪造归属。
5. 一至三个问题按步骤呈现；支持单选、多选、无选项自定义输入、允许自定义答案、上一步、下一步、提交和跳过。
6. 选项按钮有正确的 radio 或 checkbox 语义、键盘焦点、可访问名称和数字快捷键；输入法组合期间 Enter 不提交。
7. 提交期间禁用重复操作并就地显示失败；失败必须绑定产生错误的请求，切换其他待答请求时不得串扰。只有 `question.resolve` 的结构化成功响应或 `question.resolved` 事件可结束问题。
8. 到期问题不能再提交；刷新不能把本地超时伪装成 Gateway 终态，必须重新通过 `question.get` 或列表核验。
9. 密钥答案只存在于问题组件局部内存与当次 `question.resolve` 参数中，不进入 Zustand、日志、消息、草稿、测试快照或持久化。
10. 密钥绑定请求显示目标条目、用途、允许主机和替换提示；Gateway 拒绝回答或写入时原样显示结构化失败，不伪成功。
11. 多个待答请求提供紧凑的前后切换和当前位置，切换后保留各请求的组件局部草稿，密钥草稿仍不得进入全局状态。
12. 没有待答问题时不渲染占位卡，也不改变输入区高度。

## UI 验收

1. 主会话与 Quick Chat 均在输入区上方呈现问题卡；展开问题时替换输入框，折叠为紧凑栏时恢复输入框。
2. 使用现有 `aegis-surface`、`aegis-border`、`aegis-text`、`aegis-primary`、状态色和共享按钮交互，不写死主题颜色。
3. 覆盖默认、hover、active、focus-visible、disabled、loading 和 error。
4. 窄窗口中问题内容可滚动，底部操作始终可达；展开态不与输入框争夺主操作位。
5. 尊重减少动态效果偏好，不因晚到问题或答案产生消息列表位移循环。

## 不支持与待验证

- 保留现有正式 Gateway RPC `sessions.search` 会话检索，不把 Agent 工具 `sessions_search` 作为桌面 RPC 调用。
- 不在 JunQi 内自行执行 2.0 配置迁移。
- 不将原生移动端、小组件、云端共享或实验功能包装成桌面已支持。
- 真实目标 Gateway 的密钥提问、权限升级、四主题和 Windows/Linux 输入法交互待真机验证。
