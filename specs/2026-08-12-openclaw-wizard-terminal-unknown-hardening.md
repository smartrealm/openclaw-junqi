# OpenClaw Wizard 终态未知加固规格

## BUG-WIZ-04：删除未注册的配置检测 RPC

### 当前行为

JunQi 调用 `openclaw.setup.detect` 和 `openclaw.setup.verify`，但当前安装版与最新官方 Gateway 方法注册表均未定义这两个方法。

### 目标行为

删除对应客户端、导出、测试和文档声明。JunQi 不为 OpenClaw 创建配置完成或模型验证协议。

### 验收条件

- [ ] 仓库不存在两个伪 RPC 名称。
- [ ] 首次配置仍由官方 `wizard.start` 驱动。
- [ ] 业务引导不依赖伪响应。

## BUG-WIZ-05：完成门禁只消费当前官方终态

### 当前行为

Gateway 健康后，JunQi 通过伪检测决定跳过 Wizard；进入仪表盘前再次调用同一检测。

### 目标行为

首次配置默认需要官方 Wizard。同一次流程只有官方返回 `done: true` 或 `status: done` 后，才把当前内存中的 onboarding requirement 清除；进入仪表盘仍需 Gateway 健康和终态交接核验。

### 验收条件

- [ ] 新流程不会因 Gateway 健康而跳过官方 Wizard。
- [ ] 未取得官方终态时不能进入 Ready。
- [ ] 已取得官方终态后不再启动第二个 Wizard。

## BUG-WIZ-06：会话丢失保留终态未知

### 当前行为

原 `sessionId` 丢失后，JunQi 把方法不支持解释为仍需配置，并引导重启完整 Wizard。

### 目标行为

JunQi 先恢复同一 Runtime 的认证连接并尝试恢复原 `sessionId`。若官方返回 `WIZARD_NOT_FOUND`，清除不可恢复标识并进入终态未知；不推断成功、失败或回滚，不自动重放。用户只有通过明确操作才能新建 Wizard。

### 验收条件

- [ ] 会话丢失不会调用任何配置检测 RPC。
- [ ] 会话丢失不会调用交接完成路径。
- [ ] 自动进入配置页不会从终态未知启动 Wizard。
- [ ] 用户显式选择重新开始时才调用一次 `wizard.start`。

## BUG-WIZ-07：真实呈现恢复风险

### 当前行为

页面文案声称“官方检测仍要求继续配置”。

### 目标行为

页面说明旧 Gateway 未返回最终结果，当前完成状态无法核验；重新开始可能再次执行配置写入。文案不把未知状态归因为官方配置判断。

### 验收条件

- [ ] 简体中文、繁体中文和英文文案语义一致。
- [ ] 终态未知页面不显示伪成功或伪失败。
- [ ] 新建官方 Wizard 前使用可取消的二次确认明确重复写入风险。

## BUG-WIZ-08：业务引导只使用真实客户端事实

### 当前行为

业务引导调用两个伪 setup RPC，并在失败时永久隐藏。

### 目标行为

业务引导只在本地首次设置已完成、Gateway 已认证连接且当前 Runtime Identity 已核验时显示。它不表达模型探测成功，不参与首次配置完成门禁。

### 验收条件

- [ ] 任一真实前置事实缺失时引导保持关闭。
- [ ] 身份变化时重新按新身份计算，不保留旧 Runtime 状态。
