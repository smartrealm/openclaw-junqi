# Gateway 管理员权限升级规格

## 依据

- OpenClaw 官方主线提交：`87891ce2b5c8e7c72f4a8a722d73669f2e221004`
- 官方方法：`device.scopes.requestUpgrade`、`device.scopes.waitUpgrade`
- 官方会话权限：运行参数 `sessions.patch` 需要 `operator.admin`

## 验收条件

1. 日常连接权限集合保持最小，不因管理员入口存在而默认申请 `operator.admin`。
2. 只有结构化 scope 拒绝触发权限升级入口，不从错误文本推断授权状态。
3. 权限申请必须包含当前连接已协商权限与 `operator.admin`，并绑定当前已核验连接。
4. 请求标识、终态请求标识、轮换设备令牌和批准权限集合均需严格校验。
5. 轮换令牌必须先写入当前端点绑定的安全凭据作用域，再用设备令牌重连。
   首次重连必须携带 `waitUpgrade` 返回的批准权限集合完成令牌验证；验证后必须恢复日常最小权限，
   中间验证连接不得对业务层发布为已就绪。
   后续普通启动必须优先恢复该设备凭据，不能重新用共享令牌覆盖已批准 scope。
   进程恢复、插件安装重启和官方配置交接虽然必须重新解析当前所选 Runtime，但也属于后续重连；
   只有首次设置启动可以强制使用共享凭据建立信任。
   共享凭据握手一旦返回设备令牌，当前连接目标必须立即切换为仅使用设备凭据，不能让后续临时
   管理员连接继续继承共享凭据。
   设备令牌只能写入官方 `auth.deviceToken`，不得同时写入共享密钥字段 `auth.token`。
6. 原特权操作在权限恢复期间保持挂起；只在新主连接完成身份核验后重新建立一次特权连接并发送。
7. 用户取消、请求被拒绝或过期、协议不可用、身份换代和凭据保存失败均不得发送原写操作。
8. 会话设置不得直接向用户显示 `missing scope: operator.admin` 等底层英文错误。
9. 权限恢复界面复用现有主题 token、对话框和按钮状态，支持键盘、窄窗口、加载和错误状态。
10. 当前设备不得批准自己的 scope upgrade。请求创建后必须引导到官方 Control UI 或另一台已授权
    设备，JunQi 继续等待相同请求标识的官方终态。
11. Gateway 结构化返回 `AUTH_DEVICE_TOKEN_MISMATCH` 时，客户端必须删除当前端点绑定的失效设备
    凭据，并且只能使用同一已选 Runtime 的共享凭据重新签发一次。不得切换 Runtime、不得继续重试
    同一失效令牌，也不得把恢复失败投影成再次需要用户批准。该规则同时适用于权限批准后的切换和
    普通启动恢复；普通启动只能恢复日常最小权限。
12. JunQi 的设备签名和 `connect` 帧必须使用 OpenClaw 正式注册的通用 `gateway-client` 身份与
    `ui` 模式；不得冒用 `openclaw-control-ui`，后者只属于官方浏览器控制台及其共享认证代次约束。
13. 已核验主连接重连后，客户端必须查询统一特权请求器是否仍存在授权等待。存在等待时保持提示并
    重试原操作，只能由原操作的真实成功事件关闭提示；不存在等待时必须清除已经失去消费者的旧
    `scope_denied` 提示，不能要求用户再次批准同一权限。
14. 权限申请被拒绝、过期或恢复失败时，界面必须明确显示对应终态和重新申请入口，不得重新显示成
    首次“请求所需权限”的状态，也不得暗示原写操作已经执行。
15. 主连接的 `scope_denied` 不得触发管理员批准界面；只有统一临时特权请求器可以发布可恢复的
    scope 升级状态。后台可选能力探针在同一已核验连接收到结构化 scope 拒绝后必须停止周期重试，
    只在连接身份换代后重新核验，并且不得把拒绝推断为能力存在、缺席或成功。

## 未验证边界

自动化不等于目标平台系统凭据库、远程 Gateway 审批或正式签名安装包实测；这些结果必须单独记录。
