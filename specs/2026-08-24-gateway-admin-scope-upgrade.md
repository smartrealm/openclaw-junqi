# Gateway 管理员权限升级规格

## 依据

- OpenClaw 官方主线提交：`a9fdb68496d636461d11e8be29323de55636e337`
- 官方方法：`device.scopes.requestUpgrade`、`device.scopes.waitUpgrade`
- 官方会话权限：运行参数 `sessions.patch` 需要 `operator.admin`

## 验收条件

1. 日常连接权限集合保持最小，不因管理员入口存在而默认申请 `operator.admin`。
2. 只有结构化 scope 拒绝触发权限升级入口，不从错误文本推断授权状态。
3. 权限申请必须包含当前连接已协商权限与 `operator.admin`，并绑定当前已核验连接。
4. 请求标识、终态请求标识、轮换设备令牌和批准权限集合均需严格校验。
5. 轮换令牌必须先写入当前端点绑定的安全凭据作用域，再用设备令牌重连。
   后续普通启动必须优先恢复该设备凭据，不能重新用共享令牌覆盖已批准 scope。
6. 原特权操作在权限恢复期间保持挂起；只在新主连接完成身份核验后重新建立一次特权连接并发送。
7. 用户取消、请求被拒绝或过期、协议不可用、身份换代和凭据保存失败均不得发送原写操作。
8. 会话设置不得直接向用户显示 `missing scope: operator.admin` 等底层英文错误。
9. 权限恢复界面复用现有主题 token、对话框和按钮状态，支持键盘、窄窗口、加载和错误状态。

## 未验证边界

自动化不等于目标平台系统凭据库、远程 Gateway 审批或正式签名安装包实测；这些结果必须单独记录。
