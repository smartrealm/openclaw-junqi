# JunQi 首次设置页面稳定性规格

## 目标

首次设置从欢迎页到完成页必须使用同一稳定页面骨架，同时完整呈现 JunQi 安装状态和 OpenClaw 官方
Wizard，不出现主体重挂载、空白闪动、重复标题或伪完成。

## 验收条件

1. 所有 `SetupShell` 页面默认使用同一稳定内容布局，主体占用窗口剩余高度并在内部滚动。
2. `contentIdentity` 只用于重置主体内部滚动和触发内容级过渡，不能成为 `main` 的 React key。
3. 内容级过渡只修改 `opacity` 和 `transform`，时长不超过 180 毫秒；减少动态效果时立即完成。
4. 页面标题区高度一致；具体错误或运行活动与阶段标题分层呈现，相同标题和说明不能在页面内重复。
5. 存储读取、恢复、应用和已就绪状态使用共享状态面板；应用时旧表单不可交互，完成后可以继续或显式
   返回更改位置。
6. 安装进度、Gateway 启动和环境检测继续只投影真实状态与日志，不增加阶段、百分比或成功推断。
7. 官方步骤标题缺失时显示阶段标题；非空 message 在页面中只出现一次。
8. `note`、`progress`、`action`、`confirm` 和 `text` 至少占用统一的紧凑步骤高度；长选项和授权内容
   在同一稳定内容区内滚动。
9. 任意 `wizardSubmitting` 状态都隐藏旧步骤交互并显示真实等待面板；授权等待保留渠道插件说明，
   其他步骤明确等待官方下一步或终态。
10. Gateway executor 的 `progress` 使用相同等待面板并自动轮询，不显示可点击的伪提交操作。
11. `wizardError` 只显示错误状态和现有恢复操作，不同时显示旧步骤控件或旧二维码。
12. 页面继续使用 Aegis 语义主题 token、共享 `SetupShell` 和 `StatusPanel`，不增加依赖或硬编码渠道步骤。
13. 回归测试覆盖全流程稳定容器、存储状态、正文去重、通用提交等待、Done 终态等待、错误替换和滚动身份语义。
14. 环境探测与环境复核属于同一个视觉场景，必须复用同一状态卡和三项能力卡骨架；探测阶段不得呈现
   尚未收敛的局部结果。
15. 首次环境探测必须等待 OpenClaw、Gateway 与 Docker 探针全部返回后再进入复核态；Docker 失败
   显示真实不可用结果，不能在复核页进入后再补写状态并触发第二次布局变化。
16. 主体滚动位置通过稳定 DOM 引用在绘制前复位，不得通过步骤 key 重建滚动容器或其内部异步组件。
17. 常驻页面组件中的单飞锁必须绑定对应阶段生命周期；返回欢迎阶段后，前进操作必须重新可用。

## 非目标

- 不修改 OpenClaw Wizard RPC、步骤 schema、答案格式或 session 生命周期。
- 不修改安装、存储迁移、运行方式或 Gateway 生命周期语义。
- 不推断扫码成功、渠道连接成功、Gateway 健康或官方终态。
- 不合并、跳过或重新命名官方步骤，也不按 DingTalk、QuickStart 或具体供应商硬编码分支。
