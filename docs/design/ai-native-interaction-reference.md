# AI 原生交互参考与 JunQi 映射

更新时间：2026-08-11

## 范围

本文整理外部展示站和用户提供的 Loading、Thinking、Streaming、Approval、Tool Chips、Task Rows、Chat、Prompt Bar、Recommendation、Context Cards、Diff Table、Records Table、Filter Table 等示例所体现的交互模式。

示例站的开源状态和许可尚未确认。因此本文只保留交互原则与 JunQi 的实现边界，不复制其源代码、静态业务数据、图标、品牌标识或资产。

JunQi 是 OpenClaw 的桌面客户端。会话、流式消息、工具调用、任务、审批、上下文、配置和模型能力只能由 OpenClaw 的官方协议、事件和运行时结果驱动；Tauri 只负责桌面平台能力与受控呈现。

## 可复用的交互语法

- 使用短时的 `opacity`、`transform` 和高度过渡解释真实状态变化，避免大幅位移、页面跳动和无关装饰动画。
- 保持标题栏、输入框和主要操作的几何位置稳定；详情在原位展开或收起，避免异步数据到达后整体重排。
- 采用紧凑的行、胶囊、状态标签和可展开详情呈现复杂过程；摘要应先于详情，用户可按需查看证据。
- 只有真实事件到达时才按顺序展示，不以计时器演示“思考”“失败”“重试”或“完成”。
- 选择、发送、停止、重试和确认必须有清晰的可用、禁用、进行中、成功、失败和待核验状态。
- 收起的内容必须从键盘焦点顺序中移除或卸载，不能只使用透明度隐藏。动效必须响应系统的减少动态效果偏好。
- 桌面端打开外部链接、文件、目录或系统设置时必须走受控的 Tauri 路径，并经过目标和权限校验；不得假设浏览器能力。

## 模式与数据边界

| 交互模式 | 可借鉴的呈现 | JunQi 的唯一数据来源与限制 |
| --- | --- | --- |
| 长耗时加载 | 紧凑的活动指示、文字和经过时间，避免整页骨架闪烁。 | 仅绑定真实 Gateway、官方 Wizard、Tauri 本地命令或文件操作的可观测生命周期。无可计量的开始时间时不显示计时器。 |
| 思考与步骤 | 可折叠的步骤摘要、当前步骤强调和已完成步骤降噪。 | 仅投影 OpenClaw Task Ledger、运行事件、工具事件或审计记录。不得展示或生成隐藏推理链，不得用本地步骤图补足上游状态。 |
| 流式回答 | 增量内容平滑出现，完成后显示真实可用操作。 | 仅消费当前会话的官方 transcript 或流事件。不得按空格切词模拟流式，必须正确处理中文、Markdown、代码块和断线恢复。 |
| 工具调用胶囊 | 工具名称、参数摘要、结果摘要和详情在同一行展开。 | 仅显示官方事件允许呈现且已脱敏的元数据。超时或中断只能标记待核验，不能本地补写工具结果或推断副作用。 |
| 任务行 | 任务列表、进度、结果和详情保持紧凑且可展开。 | 只能映射官方 Task Ledger 或任务事件。不得按本地时钟把失败自动变为完成，也不得本地定义调度、重试或依赖关系。 |
| 审批卡 | 单个待决请求、明确选项、进度与提交反馈。 | 仅在官方协议提供审批请求、字段、选项和结果时呈现。不能以本地问卷代替审批，不能把隐藏卡片当作已拒绝或已处理。 |
| 聊天与输入框 | 固定的会话阅读区、稳定输入框、发送后的明确回执。 | 绑定稳定 `sessionId`。新会话不加载历史；Stop 只取消当前 run，历史和 Task 记忆仍由同一官方会话维护。 |
| 输入栏与菜单 | 附件、命令、模型、语音、来源菜单在输入框附近展开，并支持键盘操作。 | 每一项必须由 OpenClaw capability、官方配置或已验证 Tauri 能力提供。没有官方命令、模型、语音或来源能力时不展示可操作入口。 |
| 建议与替代方案 | 明确主建议、置信信息、替代项与确认操作。 | 仅呈现上游正式建议、审批或工具契约已给出的选项与证据。不得把模型文本或本地规则包装为可执行建议。 |
| 上下文与来源卡 | 以来源、片段、长度和可追溯链接组织检索证据。 | 仅显示官方返回并允许显示的上下文或来源；未提供来源时不伪造文件名、数量或链接。 |
| 差异预览 | 用增加、删除和未变更行让修改范围可读。 | 仅用于真实文件差异、官方结构化变更或用户尚未提交的本地预览。执行结果必须以后端或 Gateway 回执为准。 |
| 记录与筛选表 | 表头、选择、排序、标签、统计和横向滚动边界清楚。 | 字段、分页、排序和筛选必须由权威数据源支持。不得把静态 CRM、任务或来源数据作为运行时结果。 |

## 当前 JunQi 落点

- 会话与流式消息优先复用现有 `ChatView`、会话上下文和 Composer 边界，保持 `sessionId` 与 OpenClaw transcript 的一致性。
- 任务和工具过程优先复用 `OpenClawTaskLedgerPanel`、工具历史和文件预览边界；详情仅在事件证据存在时展开。
- 人工介入优先复用 `OpenClawApprovalsPanel`，不在聊天组件中另建本地审批模型。
- 页面过渡和局部动效优先使用现有 `SceneTransition`、`TabMotion`、共享 UI 组件和 `aegis-*` 语义主题 token，不增加平行主题或演示专用样式体系。
- 文件、目录、链接、权限、语音和窗口行为继续通过已验证的 Tauri IPC 与平台实现；WebView API 不能成为其唯一实现。

## 实现守则

1. 先确认 OpenClaw 官方能力、字段、事件和失败语义，再决定是否提供入口。
2. 复用现有组件、状态边界和主题 token；新组件只承载已有组件无法表达的已确认契约。
3. 每个异步交互覆盖默认、悬停、键盘焦点、禁用、加载、空数据、失败和待核验状态，并在亮色、暗色和窄窗口中验收。
4. 不使用固定延时、静态来源、空操作图标、伪模型清单、伪语音转写或虚构任务结果来制造“AI 正在工作”的错觉。
5. 对中断、断线和应用重启，保留本地派生 checkpoint 仅作投影恢复依据；终态必须重新以 Gateway 历史、运行事件或审计结果核验。

## 落地优先顺序

1. 先收敛会话流式、发送、Stop、工具详情和审批的真实状态反馈。
2. 再强化 Task Ledger 与上下文来源的紧凑展开、键盘可达性和减少动态效果支持。
3. 最后在存在权威数据契约时增加差异预览、记录表和筛选表；没有对应能力时保持不可用或不展示。
