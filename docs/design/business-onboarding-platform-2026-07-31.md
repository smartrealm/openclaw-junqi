# 业务引导平台设计

日期：2026-07-31

## 定位

JunQi 已有 Setup Wizard，负责存储位置、运行方式、OpenClaw 官方 Wizard、Gateway 身份、认证与模型就绪。业务引导平台从已验证的工作台状态开始，帮助用户掌握会话、模型、Channels、Agent、追溯、协作和工作台操作。

两者必须独立：Setup 决定“能否安全进入工作台”，业务引导决定“用户如何学习已经可用的业务能力”。业务引导不得执行安装、修改 OpenClaw 配置、请求权限或代替官方渠道授权。

## 用户体验

首次进入已验证工作台时显示一个紧凑欢迎面板，随后收起为可恢复的“开始使用”任务区。它不是全屏轮播，也不强迫用户按单一路径完成。

任务区按业务模块组织：

| 模块 | 首要任务 | 真实完成事实 |
|---|---|---|
| 会话 | 新建、命名、排序或筛选、重置 | Gateway 确认会话变更，或本地偏好已安全持久化 |
| 模型 | 配置供应商、验证模型、切换会话模型 | 当前选定 runtime 的模型探测与会话生效模型已确认 |
| Channels | 连接账号、完成官方授权、绑定 Agent | Gateway 返回账号和路由绑定投影 |
| Agent | 查看与选择 Agent、理解默认路由 | Gateway Agent 和会话身份已确认 |
| 聊天与追溯 | 发送消息、阅读执行活动、下钻来源记录 | Gateway transcript 确认消息或用户实际打开只读追溯 |
| 协作与工作台 | 创建协作、查看 Run、打开项目和终端 | 服务端授权或本地工作台资源的真实结果 |

页面内只显示当前模块任务。任务点击后导航到已有业务入口，并在附近显示一条短说明；引导不复制业务表单，不建立第二套会话、模型、渠道或协作状态。

## 会话模块

会话是默认展开模块，顺序为：

1. 新建会话并进入该会话。
2. 重命名会话，使侧栏和历史记录使用用户可识别的名称。
3. 整理会话：使用已经存在且可持久化的排序、筛选或固定能力。
4. 认识会话状态：最近活跃、运行中、归档或背景任务由现有会话投影提供。
5. 对一条已确认回复打开执行追溯，并下钻原始记录。

会话排序不得由引导组件自行改变数组顺序。若当前产品不存在用户可控、持久化的排序契约，引导只显示现有排序规则和筛选能力；新增排序能力必须先在会话领域建立偏好模型、迁移和回归测试，再注册为引导任务。

## 模块化架构

```text
业务模块的权威状态
  -> BusinessGuideFactAdapter
  -> BusinessGuideDomain
  -> BusinessGuideStore
  -> BusinessGuideSurface / 页面内提示
```

- `BusinessGuideFactAdapter` 只读取已有权威投影：Gateway 连接身份、会话、模型目录、渠道绑定、协作 Run、工作台资源和用户偏好写入结果。
- `BusinessGuideDomain` 定义模块、任务、前置条件、阻塞原因、完成事实和版本迁移规则。它不依赖 React、页面、Tauri IPC 或某个业务 store。
- `BusinessGuideStore` 只保存非敏感的引导展示偏好：已关闭、主动跳过、当前展开模块和已确认的任务完成事实版本。它不保存 token、provider key、完整配置、渠道凭据、Gateway 地址或路径。
- `BusinessGuideSurface` 是总览任务区、欢迎面板和页面内提示的共享 UI。业务页面只接收导航/高亮请求与提交经过验证的业务事件。

任务定义是声明式注册表，不在组件中根据当前机器、固定路径、固定模型、固定渠道、固定 Agent 或字符串猜测条件。每个任务声明：稳定 ID、所属模块、翻译键、前置条件、事实适配器、完成事件、导航目标解析器和不可用原因解析器。

## 生命周期

1. 仅当 Setup 已完成且当前 Gateway 的身份、认证、配置和模型门禁都已确认，才激活业务引导。
2. 引导读取权威事实，投影每个任务为 `available`、`blocked`、`in-progress`、`completed` 或 `skipped`。
3. 用户点击任务后，业务页面自行执行操作；成功后发出带实体身份的领域事件。
4. 引导重新读取事实并完成任务。事件只用于提示刷新，不能单独作为成功依据。
5. Gateway 断开或 runtime 身份变化时，未完成任务回到 `blocked`，已完成任务保留其历史完成事实，但不声称当前能力仍可用。

## 可扩展性与约束

- 新模块通过注册事实适配器和任务定义加入，不修改现有模块的组件分支。
- 任务必须能在缺少某项能力时明确说明原因，不能显示演示数据或假完成。
- 任务进度按引导定义版本迁移；新增任务不重置用户已完成的无关模块。
- 所有用户文案经 `i18next` 进入简体中文、繁体中文和英文。Gateway 返回的 Agent、模型、渠道和会话显示名保持上游原样。
- 引导不能变成权限绕过层：渠道二维码、官方 Wizard、协作审批、模型密钥和 Gateway 维护继续由已有权威流程拥有。

## 交互状态

- 可用：显示主操作，导航到真实入口。
- 受阻：说明缺少的权威前置条件，并提供已有的恢复入口。
- 进行中：反映业务操作的真实加载状态，不创建独立模拟进度。
- 已完成：显示完成事实摘要，可重新打开该功能。
- 已跳过：保留重新开始入口，不视为业务配置完成。

## 未验证边界

## 实施记录（2026-08-02）

- 已实现第一阶段总览面板：声明式任务投影、非敏感的关闭偏好和工作台内导航。
- 完成状态仅来自现有 Gateway 连接、模型、会话和 Agent 投影；渠道任务不会伪造授权完成状态。
- 页面内的任务提示、渠道绑定和 runtime identity 失效后的精确任务重投影仍待后续阶段实现。

- 会话排序的现有持久化能力需要在实施前核对；本设计不假定手动排序已经存在。
- Native、Docker、Windows、macOS、远程 Gateway 和不同渠道插件的真实引导表现需要逐目标人工验收。
