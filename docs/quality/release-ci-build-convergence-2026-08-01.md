# 发布 CI 与安装包构建收敛记录

## 依据

`v1.5.5` 的发布被同提交 CI 失败阻止，根因是 Cargo.lock 的根包版本未随桌面版本更新。`v1.5.6` 修复后，CI 的 Windows x86/x64 原生测试成功，但标签发布先等待 CI 完成，再重复执行相同 Windows 目标的发布编译。

## 变更

- 常规 CI 不再执行 Windows x86/x64 原生矩阵。
- 标签发布在来源校验完成后立即并行启动五目标构建。
- Windows 安装包构建在 Tauri 打包前测试其对应 Rust 目标。
- GitHub Release 创建前仍轮询并要求同提交的 `main` CI 成功。

## 验证边界

- 工作流语法和本地相关测试可在提交前验证。
- 下一次新标签需要确认构建在 CI 仍运行时已启动，并且 CI 失败时不会创建 GitHub Release。
- 已运行的 `v1.5.6` 工作流使用标签事件时的不可变工作流版本，不受本次修改影响。
