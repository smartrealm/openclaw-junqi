# 发布 CI 与安装包构建收敛记录

## 依据

`v1.5.5` 的发布被同提交 CI 失败阻止，根因是 Cargo.lock 的根包版本未随桌面版本更新。`v1.5.6` 修复后，CI 的 Windows x86/x64 原生测试成功，但标签发布先等待 CI 完成，再重复执行相同 Windows 目标的发布编译。

`v2.0.0` 的标签发布暴露了新的实际约束：语音运行时依赖的 `sherpa-onnx-sys` 不提供 Windows x86 与 ARM64 的预编译库。将这两个目标留在发布矩阵会让每个标签发布稳定失败，且更新清单会要求永远无法产出的安装包。

## 变更

- 常规 CI 不再执行 Windows x86/x64 原生矩阵。
- 标签发布在来源校验完成后立即并行启动三目标构建：macOS ARM64、macOS x64 与 Windows x64。
- Windows 安装包构建在 Tauri 打包前测试其对应 Rust 目标。
- GitHub Release 创建前仍轮询并要求同提交的 `main` CI 成功。
- 更新清单仅接受上述三类制品，并拒绝遗留的 Windows x86/ARM64 安装包，避免发布内容与运行时依赖能力不一致。

## 验证边界

- 工作流语法和本地相关测试可在提交前验证。
- 下一次新标签需要确认构建在 CI 仍运行时已启动，并且 CI 失败时不会创建 GitHub Release。
- Windows x86 与 ARM64 仍保留为产品兼容性待验证项；在语音依赖提供对应库并完成目标机验证前，不得重新加入正式发布矩阵。
- 已运行的 `v1.5.6` 工作流使用标签事件时的不可变工作流版本，不受本次修改影响。
