# OpenClaw 上下文压缩追溯对齐

日期：2026-08-03

## 依据

- 当前安装的 OpenClaw `2026.7.1-2` 官方压缩文档与 Gateway `session.operation` 事件契约。
- JunQi 已将 Gateway 压缩事件规范化为 `compaction` 语义块，并在主消息流展示压缩分隔线。

## 当前行为

主 Chat 会显示上下文压缩分隔线，但响应追溯投影会丢弃 `compaction` 语义块。用户在追溯中无法判断后续模型上下文是否经历过压缩。

## 目标行为

- 追溯按原始响应组顺序保留 `compaction` 节点。
- 节点只展示当前协议已提供的标识、来源序号和时间，不猜测压缩原因、token 数或摘要内容。
- 主消息流继续使用现有压缩分隔线；本次变更不复制 transcript，也不改变压缩操作。

## 实现与验证

- `projectChatResponseTrace` 将 `compaction` 语义块投影为追溯节点。
- 追溯节点卡使用现有时间线样式和多语言文案展示“上下文压缩”。
- 回归测试覆盖来源消息标识、来源序号和节点类型保持不变。

## 未验证边界

- 未连接真实 Gateway 取得压缩事件的跨连接样本。
- 未在 Windows、Linux 或 macOS 制品中完成窄窗口视觉验收。
- 压缩原因、token 前后值和 degraded 通知仍只有在上游明确提供字段后才能继续接入。
