# 仪表盘首次主题切换验证

## 问题与依据

仪表盘状态栏读取的是设置值。保存值为 `system` 时，旧实现无条件把当前主题解释为 `aegis-dark`，没有使用 `prefers-color-scheme` 的真实结果。

在浅色系统中，界面实际为 `aegis-light`，但状态栏按深色计算下一项并选择 `aegis-light`。设置发生变化，解析后的视觉主题却没有变化，因此首次点击看起来没有任何反应。

## 目标行为

- 状态栏图标、名称和轮换起点使用当前真实解析主题。
- 从 `system` 首次切换时，无论系统为浅色还是深色，都进入一种视觉不同的具体主题。
- 主题顺序只由 `AEGIS_THEMES` 定义，状态栏不维护第二份主题清单。
- 根级 `useTheme` 继续独占主题应用副作用；只需要读取当前具体主题的组件使用无副作用的 `useResolvedTheme`。

## 实现结果

- 新增纯函数 `nextTheme`，按主题唯一清单计算下一项。
- `useTheme` 复用 `useResolvedTheme` 的实时系统外观解析。
- 仪表盘状态栏删除对 `system` 的固定深色回退，改用实时解析结果。
- 回归测试覆盖浅色和深色系统下的首次轮换、完整循环以及状态栏接线。

## 验证与边界

已执行定向主题测试、TypeScript 检查和模块边界检查。生产构建和完整前端测试结果在本次变更最终说明中记录。
