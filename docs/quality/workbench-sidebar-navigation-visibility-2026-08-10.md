# 仪表盘侧栏导航可见性核对

## 当前行为与根因

当前 `main` 分支的仪表盘侧栏仍包含智能体、模型服务、通道和定时任务四个入口，前端生产构建中也能找到对应多语言键。用户当前安装的应用携带 30 项钉钉工具清单，而当前源码资源为 33 项，因此该安装实例不是当前提交生成的构建。

侧栏同时存在一个布局风险：新建对话和主要导航此前都是允许收缩的纵向弹性项。当窗口高度不足或会话区域参与布局计算时，固定功能入口可能被压缩，造成只剩会话列表的视觉结果。

## 目标行为

- 新建对话与四个主要功能入口组成固定区域，不参与纵向收缩。
- 智能体作用域、分组和排序控件位于固定功能区与会话滚动区之间；新建会话只保留顶部单一入口，并使用当前选择的智能体。
- 只有用户会话列表占用剩余空间并滚动。
- 四个入口由单一导航配置提供，路由、高亮规则和多语言键不再分散在渲染代码中。
- 模型服务只在 `/config?tab=providers` 激活，其他入口支持其子路由，不以字符串包含关系误判。

## 验证依据

- `src/components/Layout/workbenchNavigation.test.ts` 验证四个入口的完整顺序、目标路由和激活规则。
- TypeScript、模块边界、生产构建和 `git diff --check` 用于验证代码与构建边界。
- 当前本机浏览器模式无法越过真实 Gateway 启动门禁，因此不把浏览器空环境视为桌面真机视觉验收。

## 未验证边界

尚未用当前提交重新生成并安装 macOS 桌面包，也未在 Windows 和 Linux 桌面窗口中验证窄高度、亮色和暗色主题。旧安装包不能作为本次修改后的视觉结论。
