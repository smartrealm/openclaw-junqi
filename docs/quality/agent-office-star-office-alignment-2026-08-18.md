# 智能体工位空间化对齐审计

日期：2026-08-18

## 参考与许可边界

- 参考项目：[Star Office UI](https://github.com/ringhyacinth/Star-Office-UI)。其核心交互是把 Agent 状态映射到固定办公室区域，而不是按状态输出普通卡片列表。
- 参考项目 README 声明代码逻辑采用 MIT，但美术资产仅可用于非商业学习、演示和交流。JunQi 不复制、不打包或派生其像素背景、角色、精灵表、家具和动画资源。
- JunQi 继续以 OpenClaw 协作运行快照为唯一事实来源。工位位置只反映已有工作项、尝试和人工介入投影，不能表示在线、存在、心跳、任务已执行或副作用已完成。

## 根因

原 `AgentOfficeView` 虽然使用了“协调、执行、等待、介入、完成”分区，但呈现为等权的卡片网格；中心任务区与辅助区域没有空间层级，也没有使 Agent 位置表达当前协作状态，未达到办公室看板的核心体验。

## 当前行为

工位改为固定的空间化办公室平面：

- 中央大区域为执行工位；
- 左上为协调台，左下为等待区；
- 右上为介入区，右下为完成归档区；
- 五个区域始终保留，空区域仅显示真实的零计数，不补造成员或状态；
- Agent 只在其 `buildAgentOfficeProjection` 派生的区域落位，并保留当前工作项、结算进度、运行时投影和原有无障碍名称；
- 每个权威 Agent 工位都使用 JunQi 原创的像素化矢量角色；角色外观由稳定 Agent ID 决定，协调、执行、等待、介入和完成只影响已有角色的可视标记，不创建额外运行状态；
- 每个区域都使用 JunQi 原创的桌面、显示器、休息台、提示牌或归档柜矢量素材。素材使用 `currentColor` 和 `aegis-*` 主题 token，因此随现有主题变化，不需要外部精灵图、背景图或固定配色；
- 新建 Agent 成功后，JunQi 刷新协作插件的已配置 Agent 能力；无协作运行时，它出现在配置办公室的静态工位中。有协作运行但尚未被运行快照引用时，它出现在等待区的虚线“配置工位”中；该工位明确不表示当前运行参与、实时存在或执行状态；
- 当同一 Agent 出现在权威运行快照中时，配置工位被真实运行工位取代，位置完全由 `buildAgentOfficeProjection` 决定；
- 宽窗口使用三列两行的平面，窄窗口退化为单列区域顺序，避免操作或状态被裁切。

配置办公室进一步将同一协作能力快照中的不同事实拆开呈现：

- “协调席位”只投影 `coordinator` 配置；
- “已获协作许可”只投影 `allowed=true` 的非协调 Agent；
- “已配置，未纳入协作许可”只投影 `allowed=false` 的非协调 Agent。

因此已配置 Agent 不会再被误写成“未允许参与的协作席位”，也不会被当作当前运行成员。实际协作办公室仍只消费权威运行快照；没有运行时，静态配置办公室保留工位素材和角色，但不声称运行、在线或执行状态。

所有表面颜色、边框、状态色和阴影使用既有 `aegis-*` 主题 token，覆盖亮色、暗色、午夜和护眼主题，不引入固定的像素配色或外部资产依赖。

## 验证

- 协作详情、Agent 创建后能力刷新与工位投影定向测试通过，覆盖权威成员投影、未知与介入状态、空运行、配置工位、新建 Agent 刷新、空间布局标记和完整区域存在。
- 配置办公室回归测试覆盖 `coordinator`、`allowed=true` 与 `allowed=false` 三个互斥静态分区，确保未获协作许可的 Agent 不进入许可区域。
- `pnpm lint` 通过，包含 TypeScript、版本和模块边界检查。
- `pnpm build` 通过，协作插件、钉钉插件和 Vite 生产产物均已重建。
- `git diff --check` 与本次变更文件的 Emoji 扫描通过。

## 未验证边界

- 当前环境未对包含真实多 Agent 运行的界面完成亮色、暗色、窄窗口和键盘焦点的人工视觉验收。
- 未实现或暗示 Star Office 的角色移动、精灵动画、Agent 在线状态、外部状态推送协议或本地状态服务；这些都不属于当前 OpenClaw 协作快照已证明的能力。
