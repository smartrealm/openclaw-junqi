# 渠道中心界面收敛记录

日期：2026-08-10

## 依据

- JunQi 渠道状态继续来自当前所选 OpenClaw Runtime 的配置、`channels.status`、渠道目录和渠道日志。
- OpenClaw 官方渠道页面将已连接账号、可添加渠道、刷新和详情分层呈现，不在页面顶部并列暴露所有维护操作。
- JunQi 已有 `DropdownMenu`、`LoadingIndicator` 和 `aegis-*` 语义主题变量，可直接承担菜单、加载及亮暗主题一致性。

## 原有问题

- 刷新、诊断、高级配置和添加渠道同时位于页头，主次关系不清晰。
- 初次读取与后台刷新共用整页骨架，已有配置也会在刷新时消失，造成明显闪动。
- 每个账号同时展示启动、停止、退出、编辑和删除按钮，列表密度高且操作含义依赖图标猜测。
- `channelsCenter.loadingRuntime` 缺少完整多语言定义，运行时读取阶段可能显示英文回退文本。

## 当前行为

- 页头只保留刷新、添加渠道和更多操作。诊断与高级配置进入共享下拉菜单。
- 页面摘要直接展示已配置渠道、运行中账号和需要处理的账号数量，数据仅由当前真实配置与运行时状态派生。
- 只有首次读取且尚无配置时显示页面骨架。已有配置的后台刷新保留当前内容，并在页头显示读取状态。
- 账号行保留关联或登录与管理账号两个主要操作；启动、停止、退出和删除进入共享下拉菜单。
- 诊断复制与日志清理位于诊断内容内部，避免在未展开诊断时占据页面主操作区。
- 简体中文、繁体中文和英文均使用明确的渠道加载、摘要和操作文案。

## 设计边界

- 本次没有新增 Gateway RPC、渠道状态、配置字段或本地成功状态。
- 渠道可用性、账号运行状态和错误仍以 OpenClaw 结构化响应为准。
- 高级配置保留为现有配置页入口，不复制第二套配置编辑逻辑。

## 验证

- `pnpm lint` 通过，包含模块边界、版本一致性和 TypeScript 检查。
- 渠道呈现纯函数测试覆盖首次加载、后台刷新和异常计数边界。
- 完整 `pnpm test -- --runInBand` 通过。
- `pnpm build` 通过，协作插件、钉钉插件、TypeScript 与 Vite 生产构建均完成。
- `git diff --check` 通过。
