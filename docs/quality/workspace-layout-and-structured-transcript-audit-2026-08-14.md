# 工作区布局与结构化会话记录审计

## 范围与依据

本次审计覆盖工作区主要页面外框、聊天侧面板、历史消息标准化、工具结果投影和原始会话记录展示。OpenClaw transcript 的原始 `content` 块是证据来源；JunQi 的截断字符串只用于紧凑展示，不能替代原始结构。

## 发现

### LAYOUT-01 · 中等 · 页面外框宽度彼此割裂

仪表盘、活动中心、用量、技能、渠道、设置、智能体、命令和性能页面分别维护 900 至 1280 像素不等的页面上限。同一桌面窗口切换页面时，可用区域宽度发生跳变；宽窗口还产生大面积无功能留白。

目标是统一工作区页面外框为随路由视口伸缩的全宽布局，并复用同一组响应式内边距。阅读正文、对话气泡、弹窗和字段说明仍可按内容可读性保留局部行宽，不能把局部阅读宽度当作整个页面宽度。

### TRACE-01 · 中等 · 截断展示覆盖结构化证据

历史工具结果超过紧凑展示上限后，`normalizeHistoryMessage` 将 `toolOutputValue` 收敛为截断字符串，同时仍在 `rawContent` 保存 OpenClaw 原始块。“原始会话记录”此前优先读取 `toolOutputValue`，因此得到的是转义后的内容数组文本，无法递归解码实际对象。

目标是原始记录面板优先读取 OpenClaw 原始块，通过通用内容块和 JSON 解码规则生成可读投影；紧凑工具气泡继续使用有界字符串。原始载荷保留在折叠区，畸形、不完整或无法证明为完整 JSON 的文本保持原样。

### TRACE-02 · 低 · 原始记录缺少直接复制入口

原始记录面板只能查看结构化投影和折叠载荷，长记录需要手动框选。标题栏现在复用共享复制按钮：工具记录复制当前 transcript 保留的原始载荷，普通消息复制原始正文；没有已加载记录时按钮保持禁用。复制成功和失败使用不同图标、状态色与无障碍名称，不从记录标识重建内容。

### LAYOUT-02 · 中等 · 工具执行摘要与回答正文使用不同版心

同一 Assistant 响应组中的工具执行摘要使用 `min(760px, 88%)`，回答正文列使用 `min(640px, 72%)`。两者在同一头像侧栏后起始，却具有不同的右边界，长回答显著窄于其上方工具过程。

目标是让工具执行摘要和 Assistant 回答正文复用同一个响应列宽度契约。用户消息继续按自身内容对齐；窄窗口下响应列仍受可用宽度约束，不能产生横向滚动。

实现已将两处最大宽度收敛到共享常量 `CHAT_ASSISTANT_RESPONSE_MAX_WIDTH`，定向测试验证工具摘要与回答正文读取同一值；真实宽窄窗口视觉仍按下方边界待验收。

## 未验证边界

- 动态布局需要在亮色、暗色、窄窗口和宽窗口中真机复核。
- 超大工具结果仍受既有历史加载和内存边界约束，本轮不改变 Gateway transcript 大小或分页协议。
