# 导航与页签动效设计记录

日期：2026-08-02

## 问题

JunQi 已有主题切换、弹层和少量页面入场动效，但产品主导航和多数页签只切换颜色或直接替换内容。活动项没有连续的位置关系，配置、设置、业务详情和 Chat 会话切换因此显得生硬。各页面自行使用 `transition-all` 也缺少统一时长和 reduced motion 契约。

## 依据

- `src/styles/primitives.css` 已定义 Aegis motion token：80、120、180、260 毫秒及标准缓动。
- 项目已安装并使用 `framer-motion`，无需增加依赖。
- `AppLayout` 持有持久化路由滚动容器，页面动效不能移动该滚动容器，否则会导致滚动条抖动。
- 终端、编辑器和 Chat 长消息区域对重动画敏感，不能在全局 Outlet 上做退出动画或大幅缩放。

## 目标行为

1. 页面路由使用 260 毫秒以内的小幅纵向淡入，只移动页面内部场景，不移动持久化滚动容器。
2. 产品主导航及常用页签使用共享活动指示器；指示器在相邻项间以阻尼弹簧平滑移动。
3. 页签内容使用 200 毫秒的小幅淡入和纵向位移，不制造长时间空白，也不延迟业务状态切换。
4. 按压反馈仅使用轻微缩放；hover、focus-visible 和原有颜色语义继续保留。
5. `prefers-reduced-motion: reduce` 下取消位移、弹簧和页面动画，内容立即呈现。

## 首批覆盖

- 顶部产品导航 `TabBar`。
- 配置管理一级页签及内容。
- 设置一级页签及内容。
- 业务应用详情页签及内容。
- Chat 会话活动页签。
- Skills 一级页签、详情页签及内容。
- Agent Workspace 每个拆分组的活动页签及内容；指示器按 group id 隔离，避免跨 split 错位。
- 业务应用和 Skills 页面补齐共享页面入场契约。
- 已使用 `PageTransition` 的页面统一采用 Aegis 页面入场契约。

## 边界

- 不改变路由、Store、Gateway、会话或配置写入契约。
- Chat 会话内容、终端 PTY 和编辑器实例不做退出交叉淡化，避免重挂载或破坏运行状态；只对导航指示和可安全替换的轻量面板做入场反馈。
- 不在终端输出、CodeMirror、消息流和大型虚拟列表上增加逐项动画。
- 不使用循环装饰动画、强烈弹跳、模糊或大幅缩放。
- 真实 Tauri 下的亮暗主题、窄窗口、键盘焦点、低性能设备和平滑度仍需人工验证。

## 首次启动步骤切换（2026-08-07）

SetupPage 的步骤屏幕统一经过 `SetupStepTransition`。欢迎页是五个配置阶段之前的前置页，顶部步骤条保持全部未开始；点击“下一步”后环境检测阶段点亮。步骤条和底部操作栏属于稳定外壳，不再随页面横向移动；标题和内容由 `SetupStepScene` 单独过渡并保持原有居中约束。首次呈现不执行入场动画，避免应用打开时闪白。用户决策型的下一步从右侧、上一步从左侧以 12px 进入，使用 180 毫秒的近不透明位移；检测、安装、Gateway 就绪和失败等运行态使用 140 毫秒、4px 的轻微纵向入场。主内容滚动边界只允许纵向滚动，场景位移不能触发横向滚动条。顶部五阶段条使用等宽自适应网格，不再依赖 `overflow-x-auto`；窄窗口下文案允许换行，阶段关系和连接线保持可见。

步骤状态提交后立即卸载旧屏幕，任何时刻只有当前步骤页拥有组件生命周期。动效只作用于新屏幕入场，不保留退出页的组件引用、异步 effect 或指针层级。系统开启 `prefers-reduced-motion` 时取消位移与动画时长，内容直接切换。

当前已通过方向计算、当前页入场状态和 Setup 壳层回归；本机 macOS 正常使用链路已获得安装后反馈。真实 Tauri 的专项帧时间、窄窗口和低性能设备平滑度仍待人工验收。
