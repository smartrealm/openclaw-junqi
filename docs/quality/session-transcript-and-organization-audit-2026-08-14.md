# 会话组织与 transcript 展示审计

## 范围

本次审计覆盖会话置顶、未读、分叉、分组、归档、历史会话首次定位、新建空会话输入状态，以及普通回复和工具结果的结构化展示。

## 上游依据

- OpenClaw `sessions.patch` 接受 `pinned`、`unread`、`archived` 和 `category`。
- `sessions.patch` 的持久化条目使用 `pinnedAt`、`markedUnreadAt`、`lastReadAt` 和 `archivedAt` 表达状态，不回显同名布尔字段。
- 归档写入支持 `expectedSessionId`，用于防止同一 key 的会话身份轮换后误改新的 transcript。
- 会话分叉由 `sessions.create` 的 `parentSessionKey` 与 `fork: true` 所有；客户端只呈现官方返回的新会话。
- transcript 内容以 OpenClaw 返回的角色、内容块、工具输入和工具结果为事实来源。JunQi 只能生成只读展示投影，不改变原始内容。

核对范围为 2026-08-14 获取的 OpenClaw 主线 schema、Gateway handler 和 Control UI 操作实现。项目安装版本只用于复现，不作为能力开关。

## 当前缺陷

### SES-01 会话组织成功后被误判失败

严重级别：P0。

客户端在 `sessions.patch` 返回后读取 `entry.pinned`、`entry.unread` 和 `entry.archived`。官方条目实际使用时间戳字段，因此 Gateway 已完成写入时，JunQi 仍抛出 `SESSION_ORGANIZATION_RESPONSE_INVALID`。结果是服务端状态和本地投影分离，并将内部错误码直接显示给用户。

### SES-02 归档语义与身份围栏不完整

严重级别：P1。

界面将 Gateway 归档描述为“归档到本机”，与实际持久化位置不符。归档调用也没有携带已知的 `sessionId`，无法利用官方 `expectedSessionId` 防止身份轮换竞态。

### SES-03 历史会话首次尾部定位过早完成

严重级别：P1。

历史元数据标记为已加载后，界面立即把当前会话记为“已完成首次尾部定位”。虚拟列表内容可能尚未提交，此时滚动调用对空列表或旧列表生效；真实消息随后出现时不会再次定位。

### SES-04 新建空会话错误显示历史预热

严重级别：P1。

新建会话只有在创建回执、会话身份和空 leaf 事实同时保留时才能跳过 `chat.history`。任何中间投影丢失该事实，输入框就会被“正在加载最近对话”禁用。新建空会话不应等待不存在的历史。

### SES-05 transcript 结构化内容展示不一致

严重级别：P1。

来源记录侧栏已经可以解析部分结构化工具结果，但普通 assistant 回复中的完整 JSON 文档和工具卡片输出仍可能以压缩字符串显示。展示层应在确认完整 JSON 后格式化缩进；无法完整解析时必须保留原文，不能猜测修复。

## 目标行为

- 会话组织操作按官方持久化字段核验回执，只在可验证成功后更新本地投影。
- 已知 `sessionId` 的归档操作携带 `expectedSessionId`；未知身份时保留现有 key 级调用，不伪造身份。
- 内部协议错误使用可理解的本地化提示，技术错误码不进入普通通知正文。
- 普通新建空会话立即可输入；只有身份未知且 transcript 尚未读取的已有会话显示历史加载。
- 侧栏切换、页签切换、新建、分叉、关闭页签和删除当前会话后的回退统一在当前会话内容进入虚拟列表后执行一次无动画尾部定位。
- 完整 JSON 文档以 JSON 代码块或等价的只读结构化视图展示；工具输入、工具输出和原始载荷保持各自证据边界。
- 不完整 JSON、普通文本和未知内容块保留原文。
