# 钉钉桌面工作台 UI 审查

## 审查范围

- `src/pages/BusinessApplicationsPage.tsx`
- `src/components/BusinessApplications/`
- `src/components/Layout/NavSidebarPanels.tsx`
- `src/styles/` 与共享按钮、选择器、空状态组件
- OpenClaw 官方主线 `ff1d91f6711b301ad0bb8f8f9485bfb05d770d84`
- DWS 官方主线 `bea76da8ba5091154a31779e2850d652c212aef6`
- Apple Human Interface Guidelines、Microsoft Fluent 2 与 Ant Design 官方设计规范

## 现有问题

### 信息层级拥挤

页面标题、连接状态、账号、筛选条件、Profile、目录边界、工具契约、参数、执行动作和技术证据同时常驻。用户第一次进入时难以判断下一步应先选择操作、处理接入问题还是填写参数。

### 字体和控件密度失衡

主体信息大量使用 9 至 10.5 像素字号，搜索、筛选和操作按钮集中在 24 至 28 像素高度。技术性次要信息与任务名称、错误和主操作的视觉差异不足，长时间桌面使用时扫描成本较高。

### 三栏布局没有形成稳定焦点

独立筛选栏、工具表格和详情栏同时出现。筛选栏默认折叠后只留下竖排文字，仍占用视觉注意力；窄窗口依赖命令式宽度判断折叠侧栏，选择工具后详情重新展开会挤压目录，不能形成明确的单任务焦点。

### 表格重复信息并削弱可扫描性

工具已经按业务域分组，表格仍重复展示业务域列；操作说明只存在于详情，用户需要逐项打开才能理解工具。整行鼠标点击与内部按钮并存，键盘焦点和选中状态的语义不够直接。

### 审计记录暴露过多低频证据

Session、run、tool call、DWS 路径、核验路径、资源 ID 和恢复事件同时铺在列表正文。它们对故障排查重要，但不是日常扫描所需，导致操作名称、状态、账号和时间失去主导地位。

## 设计依据

- Apple 的桌面与布局规范要求把重要信息放在阅读顺序前部，按关系分组，使用渐进披露承载次要信息，并让可调整窗口保持一致且可用的布局。
- Fluent 2 使用空间接近性建立分组和层级，以四像素节奏维持一致性；正文层级采用清晰的 12 至 14 像素范围，并要求响应式布局通过重排、显隐或重新组织保持焦点。
- Ant Design 的数据展示规范要求按重要性、操作频率和关联度组织信息；表格适合比较结构化数据，窄容器更适合可扫描列表，折叠用于低频长内容。

这些资料只用于界面组织和可访问性，不作为 OpenClaw 或 DWS 能力依据。工具、状态、权限和执行结果仍只来自当前 Session 的 OpenClaw 投影与 DWS 实际响应。

## 目标方案

1. 页头使用统一的 15 像素标题、11 至 12 像素状态与 32 像素操作区，只保留视图定位、真实状态、当前身份和刷新。
2. 工具视图由目录与检查器两部分组成。搜索、业务域和读写筛选合并到目录工具栏，删除独立筛选侧栏及其宽度状态。
3. 工具目录保留业务域分组，删除重复业务域列；每项直接展示名称和说明，并以单一按钮承担键盘与鼠标选择。
4. 详情面板提升名称、正文和表单字号，固定主操作区；Profile、参数错误和写入风险靠近执行动作，技术契约继续按需展开。
5. 宽窗口并排显示目录与详情；窄窗口只显示当前任务，选择工具进入详情，关闭详情返回目录。
6. 审计列表正文只显示操作、来源、状态、账号、影响和时间；Session、run、tool call、路径和资源证据放入可访问的技术详情。
7. 接入页保留现有真实就绪步骤、账号和事件配置，不改变 OpenClaw、DWS 或 Gateway 状态语义，只统一字号、间距、对齐和分区标题。

## 边界

- 不新增工具、RPC、权限状态或本地成功语义。
- 不翻译或改写 OpenClaw 与 DWS 返回的动态名称、错误和结果。
- 不把目录可见性解释为钉钉业务权限。
- 不在本轮改写事件配置、写后核验或审计协议。
- 真实 macOS、Windows 和 Linux 安装包视觉表现仍需目标平台验证。

## 验证要求

- 组件行为测试覆盖工具分组、选择语义、描述信息、技术详情和三语言键集合。
- 生产构建、TypeScript、模块边界、完整前端与脚本测试通过。
- 浏览器连续验证加载、成功、失败和空状态，并检查亮色、暗色、窄窗口、键盘焦点与目录详情切换。
- 若无法取得真实 Gateway、DWS Profile 或目标租户，必须将这些状态明确记录为未验证，不能用夹具冒充。

## 插件兼容性故障收敛

2026-09-11 真机截图证明 OpenClaw `2026.7.1-2` 会拒绝安装声明插件 API `>=2026.8.1` 的固定钉钉插件。旧界面仍将该状态呈现为可重装，并同时在就绪面板与安装对话框重复显示原始错误。

根据 OpenClaw 官方插件安装契约，本地归档在安装前必须通过兼容性校验；固定归档不会自动选择历史兼容版本。本轮因此保留插件已验证的 `2026.8.1` 下限，将兼容范围写入固定包元数据，并在 Rust 安装边界与业务台界面使用同一真实状态。确定不兼容时，界面只提供 OpenClaw 官方更新入口，不再发起注定失败的插件安装。

官方依据：

- https://docs.openclaw.ai/cli/plugins/install
- https://docs.openclaw.ai/plugins/compatibility
- OpenClaw 官方主线 `e8e68e84e4559ed2bb0455335267c800e1fa5aca` 的 `src/plugins/install-shared.ts`

## 更新维护探针的运行时一致性

目标 macOS 复现表明，官方更新器已经能使用兼容 Node.js 完成 OpenClaw 升级，但协作维护探针把 npm 启动器解析为 JavaScript 文件后直接执行，解释器再次由通用 PATH 选择。系统存在另一个不兼容 Node.js 时，维护探针会错误返回运行时不可用，界面最终表现为更新失败。

本轮将固定原生 CLI 目标扩展为同时携带已核验 `NativeOpenclawRuntime`。协作探测、安装和恢复命令继续绑定原状态目录与配置文件，但改由同一 Node.js 和 OpenClaw 入口执行。Docker 分支保持不变，不增加版本号能力开关或备用安装路径。

自动化已覆盖错误 JavaScript 启动器与已核验 Node.js 启动器并存时的选择结果，以及插件清单对旧、新 Gateway 的宿主兼容性判断。目标机器上的官方 `update --dry-run --json` 已返回当前稳定版本和同一安装身份；完整钉钉插件安装、Gateway 重启与 Session 工具投影仍需在解锁后的 Tauri 窗口继续核验。

## 非交互安装确认与错误诊断

2026-09-14 的真机截图表明，固定钉钉归档安装失败时，OpenClaw 会先把飞书、微信的重复插件标识作为配置警告写入标准错误，随后再输出钉钉安装的真实失败原因。JunQi 旧实现只取第一条标准错误，导致无关配置警告遮蔽真实错误。OpenClaw 官方主线同时确认，非交互插件安装和启用需要由调用方明确接受插件声明能力；安装策略警告使用独立确认参数，`--force` 不能替代该确认。

本轮将“确认安装”绑定到已校验固定归档的能力确认与安装策略警告确认，OpenClaw 的阻止规则和失败仍保持终止语义。安装与启用命令均显式接受插件声明能力；本地 `.tgz` 固定归档不再携带只适用于 npm registry 安装的 `--pin`，其来源固定性继续由资源元数据、SHA-256 和归档内版本契约共同保证。错误提取会跳过前置配置警告并优先显示真实失败行，不会把飞书、微信警告当成钉钉安装结果，也不会修改或删除已有插件配置。

官方依据为 OpenClaw `v2026.9.4` 标签提交 `3a9d69db306cd7f081e06254cb89c4bcc14a7107` 以及主线提交 `5685a8f3ea2361c86d1680bfb7f95ab48ed7edc2` 的 `src/cli/plugins-cli.ts`、`src/cli/plugins-install-command.ts`、`src/cli/plugin-capability-consent.ts`、`src/cli/install-policy-warning-acknowledgement.ts` 与 `src/config/io.warnings.ts`。
