# 目标运行环境 Node.js 决策审查

日期：2026-08-24

## 结论

JunQi 的 Node.js 决策只读取目标桌面上、当前所选 Runtime 可见的可执行文件及其自带 npm，并用当前 OpenClaw 包的 `engines.node` 契约判断是否可复用。开发机上的 Node.js、路径和版本不参与发行应用的判断。

已有 `node` 可执行文件不等于可以运行 OpenClaw：版本必须满足准确的 `engines.node` 范围，且 npm 必须是该 Node 发行版自带的可执行 npm。外部 PATH 中的 npm 不能与另一套 Node 混用。

## 官方依据

已更新 OpenClaw 官方仓库并核对 `origin/main` 的 `95b69efcc161548b364ff681b2f46c66742930cb`。该提交的根 `package.json` 声明：

```text
>=22.22.3 <23 || >=24.15.0 <25 || >=25.9.0
```

该范围中的 `>=25.9.0` 没有上限，因此 `v26.1.0` 满足当前官方主线范围，必须复用。实际安装仍以当前目标 npm 包返回的 `engines.node` 为准；若目标包返回的范围不包含已检测版本，例如只允许 22.x 与 24.x 而机器只有 `v23.8.0`，才准备兼容运行时。任何满足目标包范围且拥有自带 npm 的目标机器 Node.js 都必须被复用。

## 决策与修复

1. `check_setup_node` 对已安装 OpenClaw 读取已安装包的 `engines.node`，尚未安装时读取目标 npm 包元数据；通过该契约探测当前所选 Runtime 的 Node.js 与 npm。
2. 明确配置的 Node 路径是独占候选，不会悄悄切换到 PATH 的另一套 Node。未配置时按目标平台发现系统候选；Windows 会按 PATH 顺序核对全部发现候选。
3. 修复前，前端把“没有 Node.js”和“检测到 Node.js 但版本不兼容”都写成“正在安装 Node.js”。修复后，后者会显示检测到的版本和目标 OpenClaw 所需范围；没有可执行 Node 时只显示目标范围。
4. OpenClaw 安装阶段再次发现不兼容时，Rust 进度事件同样传递版本和范围，避免进度日志回退为泛化提示。
5. 真正进入安装入口前仍再次解析同一完整 Node/npm 契约。若在两次检查之间已有兼容运行时可用，安装入口直接返回该运行时，不下载、不覆盖现有环境。

注册表暂时不可用时，首次纯探测可用宽松要求回报目标机器的 Node/npm 状态，但不会用它作为安装写入的依据；实际安装边界必须重新取得准确目标契约，无法取得时保留失败，不猜测版本范围。

## 验证边界

自动化覆盖目标范围、已检测不兼容版本和缺失版本的展示分支，以及后端进度参数。未在 Windows、macOS 和 Linux 的全新目标机器上完成系统安装器真机验证；各平台的 PATH、版本管理器和权限行为仍需在目标机器验证。
