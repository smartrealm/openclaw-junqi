# JunQi 全局轻量视觉审计

日期：2026-08-10

## 审查范围

- 四套 Aegis 主题的表面、边框、强调色、阴影与遮罩令牌。
- 共享卡片、下拉菜单和对话框。
- 仪表盘、设置、智能体、渠道、聊天和终端等高频页面对共享视觉层的使用情况。

## 当前问题

1. 深色主题的背景、侧栏、面板和卡片亮度差距偏大，同一页面容易形成多层厚板叠放感。
2. 菜单与浮层阴影普遍使用 32 像素模糊和较高不透明度，共享下拉菜单仍使用通用 `shadow-2xl`。
3. 共享对话框使用固定黑色高不透明遮罩和通用大阴影，没有随当前主题调整。
4. 通用卡片使用 12 像素圆角、20 像素内边距和悬停上浮，多卡片页面视觉重量偏高。
5. 默认蓝色强调面的透明度较高，选中项、消息气泡和状态表面容易抢占内容注意力。

## 目标方向

- 页面主体依靠排版、间距和一像素分隔线建立层级，普通容器不依赖明显阴影。
- 菜单、弹窗和临时浮层只使用短距离、低不透明度阴影。
- 深色主题各表面保持可辨认但更接近，避免多层灰蓝色块叠加。
- 普通卡片默认使用 8 像素圆角和较紧凑内边距，悬停只改变边框与背景，不产生漂浮感。
- 强调色保持单一蓝色家族，并降低普通表面的饱和度和透明覆盖强度。
- 所有调整继续由语义主题令牌和共享组件承担，业务页面不得复制平行样式。

## 保留边界

- 危险、警告、成功和运行状态颜色继续承担语义，不因视觉简化而改成同一种灰色。
- 主操作按钮仍使用实色强调，次要操作使用描边、柔和或文字样式。
- 终端 ANSI、图表数据色和品牌图像不纳入本轮统一改色。
- 本轮不改变 OpenClaw 协议、业务状态、页面路由和数据加载行为。

## 验收方式

- 自动化检查四主题令牌、共享组件类型和现有交互测试。
- 生产构建确认 Tailwind 与主题变量能够生成有效样式。
- 本地 WebView 页面检查亮色与暗色下的仪表盘、设置、智能体、渠道和聊天主要区域。
- macOS、Windows 和 Linux 的真实桌面视觉仍需后续真机验收。
