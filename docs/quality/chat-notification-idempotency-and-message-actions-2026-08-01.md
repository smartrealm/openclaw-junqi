# Chat 通知幂等与消息操作栏修复

## 依据

Gateway 同一条助手回复可能先通过流结束事件到达，再通过持久转录事件到达。两条路径都需要保留，因为前者负责流式 UI 收尾，后者负责重连和离线转录恢复；它们不能靠正文相同来判断是否是同一事件。

## 当前行为

`App.tsx` 的两条路径各自调用通知服务，而持久通知没有上游事件身份。结果是同一回复可以重复出现 toast、声音和通知历史。助手消息的预览与复制按钮位于绝对定位容器，短气泡内容可能被按钮遮挡。

## 目标行为

- 当 Gateway 提供运行、客户端消息、原生消息或消息序号身份时，使用 `sessionKey + role + identity` 生成稳定幂等键。持久化 `session.message` 事件优先使用其显式 `runId`，以便与流结束事件对应同一键；客户端、原生消息身份和序号只作为回退。实时流结束后，转录投影按事件 `runId` 判断该运行是否已经展示；若旧 Gateway 仅在持久事件提供不同的消息内部 ID，则只在同一会话、短时窗口内与刚完成实时回复的规范化正文严格一致时，认定为同一传输投影。该关联不跨会话，也不用于重连后的纯转录通知。通用 `onMessage` 回调只更新会话状态，不参与通知，因为它可能镜像这两种投影且不保证携带运行身份。
- 前端通知服务在当前进程内拒绝重复键；Tauri 持久层使用同一键拒绝跨重连、跨窗口刷新造成的重复写入，并向 renderer 返回是否实际插入。声音、toast 和后台系统提示只在插入新记录后呈现，因此不同消息 ID 的旧 Gateway 镜像也不会产生第二次可见提示。
- Tauri 读取和写入持久库时会清理历史版本遗留的完全相同幂等键，并保留最新记录。对于 Gateway 旧事件模型中同一回复使用不同消息 ID 的兼容缺口，额外只合并同一聊天会话、同一角色、同一标题和正文、且在两分钟容忍窗口内产生的 `chat:*` 记录，保留最新记录；该回退不处理无身份通知、不同会话、不同角色或超过窗口的事件。
- 通知中心读取、实时推送、终端工具生命周期写入、已读和清空均经由 `persistentNotificationRepository` 的 typed command 边界；组件不直接拼装通知 IPC 载荷。
- 缺少身份或没有可见正文的聊天事件不发布通知；正常路径始终按上游身份去重，只有上述 Gateway 传输镜像兼容边界才使用受会话、角色和短窗口约束的展示字段回退。非聊天通知仍可作为独立事件保存。
- 助手消息的预览和复制操作栏在气泡内正常排版，保持现有 `ChatIconButton` 的多语言 Tooltip，不能遮挡正文。

## 验证

- TypeScript 单测覆盖 live/durable 两条路径的相同幂等键、通用回调不发布通知，以及缺失身份或空正文不发布边界。
- TypeScript 单测覆盖 `session.message` 的 `runId` 即使消息记录未提供客户端身份，也能透传到通知边界；覆盖实时完成和消息内部身份不同的持久转录不会再次投影；覆盖缺失外层运行身份的即时持久镜像、纯转录和跨会话同文边界。
- Rust 单测覆盖相同键只保留一条、不同运输消息 ID 的即时聊天镜像只保留一条、跨会话或超过窗口不合并、无键事件仍保留两条，以及旧版本即时重复记录的窄范围迁移。
- 通知命令契约测试覆盖通知仓库为唯一 renderer IPC 出口，终端可见时的自动已读仍通过该出口执行。
- 仍待桌面真机验证：流结束与转录事件同时到达时只出现一次提示；旧版本的即时重复历史记录会在首次读取时收敛为最新一条。
