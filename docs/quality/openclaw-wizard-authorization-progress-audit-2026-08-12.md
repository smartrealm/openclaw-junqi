# OpenClaw 向导授权推进审计

## 范围与依据

本次审计覆盖 OpenClaw Wizard 中渠道授权地址的呈现、当前步骤提交、插件轮询等待和二维码销毁。依据为钉钉官方连接器 0.8.24、本次核对的连接器主线 `src/onboarding.ts`、OpenClaw Wizard 正式步骤协议，以及 JunQi 当前 `wizard.next` 调用链。

## 根因

钉钉连接器在终端二维码生成失败后，先通过 `prompter.note()` 返回授权地址。只有用户确认并提交该官方提示步骤，连接器才会继续询问是否使用地址授权；后续官方提示步骤再次提交后，连接器才调用 `waitForDingtalkRegistrationSuccess()` 开始轮询。

JunQi 已把当前步骤的一次性授权地址投影为二维码，也会在提交期间等待同一个 `wizard.next` 请求，但界面仍把授权步骤的主要操作显示为通用“下一步”，授权区域没有说明扫码后需要继续提交当前官方步骤。用户完成扫码后，连接器尚未进入轮询，JunQi 也没有可消费的官方状态事件，因此页面看起来没有反应。

## 修复边界

- 当前步骤存在正式 `externalUrl`、一次性授权地址或 `deviceCode` 时，显示授权专用说明和主要操作文案。
- 用户触发主要操作后仍只调用当前官方步骤的 `wizard.next`，不新增授权 RPC，不从扫码时间、页面可见性或文本内容推断成功。
- `wizard.next` 等待期间销毁当前二维码并显示“等待官方插件返回结果”的状态。
- 下一官方步骤、成功、失败、超时和恢复均继续由 Gateway 与插件结果驱动。

## 验收条件

1. 授权二维码旁明确说明扫码或浏览器授权后需要继续。
2. 授权步骤主要操作不再显示通用“下一步”。
3. 提交后旧二维码不可继续操作，界面进入等待态。
4. 非授权步骤的操作文案和提交行为不受影响。
5. 不增加按渠道名称、插件版本或英文提示文本判断的分支。

## 未验证边界

钉钉连接器当前没有在二维码可见阶段向 Wizard 客户端发布扫码完成事件。JunQi 无法在用户未提交当前官方步骤时自动得知扫码结果；自动推进会跳过插件拥有的确认步骤，因此不属于客户端可实现边界。

## 验证结果

- 修复前新增的静态渲染回归测试按预期失败，证明授权区缺少继续说明且主要操作仍为通用“下一步”。
- 修复后配置页面定向测试 13 项通过。
- 完整 `pnpm test` 通过，无失败项。
- `pnpm lint` 通过，模块边界检查覆盖 895 个文件，版本一致性和 TypeScript 检查通过。
- `pnpm build` 通过，协作插件、钉钉业务插件、TypeScript 和 Vite 生产构建完成。
- `git diff --check` 通过。
- 钉钉真实扫码后的官方步骤推进仍待新桌面安装包真机复验。
