# 工作区首屏数据就绪记录

日期：2026-08-05

## 问题

原启动门禁将 `sessions.list` 失败视为可进入工作区的终态。于是仪表盘和侧栏先以空数据渲染，
后续轮询才填充会话和智能体，造成明显的布局跳变和错误的就绪感。

## 调整

- 工作区只在 Chat 会话快照已确认，且共享会话与智能体数据组均已在当前 Gateway 连接后成功读取时放行。
- 读取时间与 `connectionStartedAt` 比较，旧连接遗留的缓存时间不再满足新连接的门禁。
- 首批读取失败保留全局失败和重试操作；不再将空仪表盘作为恢复界面。
- 重试同时重新读取 Chat 会话投影以及共享会话、智能体数据组。
- 设置、终端、日志等 Gateway 可选路由维持原先的非阻塞访问策略。

## 验证

- `App.startup.test.ts` 覆盖当前连接时间围栏、失败不放行及本地化重试入口。
- 尚未完成 macOS、Windows、Linux 的冷启动和断线恢复真机验收。
