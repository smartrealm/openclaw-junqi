# 新手引导终态恢复记录

日期：2026-08-06
状态：自动化验证完成，待桌面真机验收

## 依据

- OpenClaw 官方 Wizard 通过 `wizard.start`、`wizard.status`、`wizard.next` 与 `wizard.cancel` 管理进程内会话。
- 官方向导的 `Done` 仅表示向导会话到达终态；JunQi 的工作台准入仍必须验证所选 Gateway、当前配置和实时模型探测。

## 当前行为

Gateway 服务交接时，终态确认可能遇到 WebSocket 连接超时。随后点击重试会向已经被官方回收的进程内会话发请求，界面只显示 `wizard not found`，掩盖了原始的连接或模型验证问题。

模型实时探测的原始失败详情会进入诊断日志，但原界面只显示笼统的模型未就绪，用户无法判断是认证、模型缺失还是超时。

## 目标行为

- 把 Gateway 进程就绪与经认证的桌面 WebSocket 连接分开说明。
- 对终态说明的确认超时，只在配置结构完整时进入既有的 Gateway 与模型验证门禁。
- 重试遇到官方已回收的 Wizard 会话时，重新核验当前运行时配置和实时模型；不得重放答案、凭据或旧会话标识。
- 已由 OpenClaw 返回并经过脱敏的模型探测详情在操作附近展示，不能用本地状态替代上游结果。
- 只有 Gateway、配置和模型三项验证均通过，才能进入工作台。

## 验证范围

- `setupOnboardingRegression` 覆盖终态确认和已回收会话的恢复分支。
- 尚未在 macOS、Windows、Linux 真机复现服务交接期间的网络和凭据库交互。
