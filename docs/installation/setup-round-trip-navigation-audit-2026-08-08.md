# 首次启动往返导航审计

日期：2026-08-08

状态：根因已修复，本机 macOS 验收结果见[首次启动往返导航修复验证](setup-round-trip-navigation-validation-2026-08-08.md)。本文保留审计时的代码与 Git 事实，不作为验证结果的重复记录。

## 当前目标

修复“环境检测下一步、数据位置上一步、环境检测再次下一步”失效，同时保留能够解释前进和返回方向的轻量动效。

## 审计时确认的问题

### BUG-SETUP-01：退出动画保留有状态步骤页

Setup 页面包含安装事务、存储状态、异步回滚和多个组件本地引用。退出动画让旧页与新页短暂共存，使步骤状态已经变化但旧组件尚未卸载。快速往返时，页面本地锁和 effect 清理不再与导航提交同步。

影响：当前页面可能被退出页面的生命周期影响，用户看到新页面后再次操作却无法稳定进入下一步。

### BUG-SETUP-02：按钮状态与真实动作锁分离

环境页按钮只读取 `checkingDocker`，处理器还读取导航离开锁、环境动作锁和 Docker 探测引用。命中后处理器静默返回，界面没有禁用、加载或错误反馈。

影响：按钮呈现为可用，但点击没有任何反馈。

### BUG-SETUP-03：回归测试没有运行真实往返链路

审计时的测试分别验证导航 reducer、动作 reducer 和动效计算，没有把环境页、数据位置页、异步返回和步骤动效放入同一行为链路。

影响：自动化通过不能证明“下一步、上一步、下一步”可用。

## 修复方向

1. 步骤变化时立即卸载旧页面，只对新页面执行方向性入场动画。
2. 环境动作使用同步单飞引用保护重复事件，同时镜像为可渲染状态；按钮和处理器读取同一忙碌语义。
3. 回归测试覆盖导航状态与动作状态的完整往返序列，并验证动效契约不再定义退出页面交互。

实现结果、命令输出、安装包校验和人工反馈统一记录在[修复验证](setup-round-trip-navigation-validation-2026-08-08.md)，避免审计文档同时承担当前状态说明。
