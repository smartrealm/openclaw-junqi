# ADR-0003：延期企业控制面，优先完成单用户桌面闭环

状态：已决定，延期实施

日期：2026-08-25

## 背景

JunQi Desktop 当前定位是 OpenClaw 的跨平台桌面客户端。最新版 OpenClaw 明确以一个 Gateway 对应一个可信操作域；不同租户需要独立完整 Gateway Cell。租户、SSO、集中授权、跨 Cell 审计、配额和多主机生命周期不属于单个 Gateway 或 JunQi 本地客户端能够独立完成的能力，需要额外的企业控制面、接入层和 Cell Controller。

当前单用户桌面产品仍有安装、Gateway 生命周期、设备授权、会话交互、智能体工作台、配置、渠道、协作、诊断、主题、窗口行为和跨平台打包等需要继续真实验证和收敛的链路。此时引入服务端、租户模型和第二种连接方式会同时扩大身份、凭据、部署、网络和故障恢复边界，并降低单用户链路的完成度。

## 决策

当前阶段不实现企业控制面，不创建服务端、租户数据库、SSO、企业接入层、Cell Controller、配额服务或企业管理页面。JunQi 不增加未被当前单用户功能消费的企业接口、类型、配置开关、占位页面、模拟数据或兼容分支。

企业化方向保留为后续独立系统：企业控制面负责身份、租户、成员、角色、Cell 注册、准入、审计索引和配额；每租户使用独立 OpenClaw Gateway Cell；JunQi 只连接当前用户获准访问的 Cell。未来实施仍必须复用 OpenClaw 官方可信代理、命名角色、设备身份、Gateway v4 协议和生命周期契约，不得在 JunQi 中另造 Agent、会话、工具、权限或运行时语义。

当前产品与工程优先级固定为单用户桌面闭环。所有后续功能判断先回答以下问题：是否直接提升一个用户在一台受控桌面客户端中安装、连接、配置、使用和恢复 OpenClaw 的完整性。不能直接提升该链路的企业预留实现暂不进入代码。

## 单用户完成范围

单用户阶段至少需要持续收敛以下真实链路：

1. 首次安装与更新：目标机器的 Node.js、npm、Git、OpenClaw 和运行方式选择有明确来源、权限边界、失败恢复和目标平台验证，不参考代理开发机环境作决定。
2. Gateway 生命周期：启动、停止、重启、恢复、服务交接、配置身份和 Runtime Identity 只经过统一协调入口，所有页面共享真实状态和错误语义。
3. 身份与权限：设备配对、scope 申请、管理员临时连接、凭据轮换、撤销和系统凭据库存储符合官方协议，不默认持有 `operator.admin`，不通过错误文本推断权限。
4. 会话交互：发送、排队、转向、中止、重连、历史恢复、附件、审批、问题和工具事件忠实投影 OpenClaw 状态，输入区在亮色、暗色、窄窗口、键盘和输入法下完整可用。
5. 智能体与工作台：智能体、办公室、活动、任务、工作区和协作只展示 OpenClaw 或正式插件能够证明的事实，不用本地伪状态制造成功或运行结论。
6. 模型、渠道与配置：选择器、Wizard、Provider、渠道插件、二维码和配置写入遵守当前官方 schema、`config.get` envelope、`baseHash` 和最小 patch 契约。
7. 桌面系统行为：主窗口、最小化恢复、托盘、宠物窗口、系统通知、深链、外部链接、凭据库和文件权限在 macOS、Windows 与 Linux 上分别核验。
8. 发布质量：自动化、静态检查、Rust 检查、生产构建、安装包内容、签名、公证、升级和卸载结果分层记录，不把本地 ad-hoc 制品描述为正式发布包。

“单用户做好”不以功能数量判断，而以端到端链路可复现、失败可恢复、状态不伪造、权限最小、跨平台边界明确和 UI 交互完整为验收标准。

## 企业化重新启动条件

只有同时满足以下条件，才重新建立企业控制面的规格和实施计划：

- 单用户核心链路已完成自动化与至少目标发布平台的真实验收，未保留阻断安装、连接、会话和恢复的高优先级缺陷。
- 已明确企业客户的身份提供方、租户隔离等级、部署形态、数据驻留、审计保留、配额执行点和运维责任。
- 已决定控制面服务的部署与维护主体，并具备服务端数据库、Secret Manager、TLS、监控、备份和灾难恢复基础设施。
- 已以届时最新 OpenClaw 官方主线重新核对多租户 Cell、可信代理、命名角色、设备配对、审计、用量和宿主生命周期契约。
- 已单独完成威胁模型、跨租户隔离测试、撤权时延、Cell 升级回滚、故障域和容量验证计划。

重新启动时先创建新的 `specs/` 与 `plans/` 文档；本 ADR 只保存长期边界和延期决策，不作为可直接编码的接口规格。

## 结果

- 当前代码继续保持一个桌面客户端连接一个由用户明确选择并核验的 OpenClaw Runtime，不增加企业模式双轨。
- 企业设计不会以占位 UI、无消费者抽象、硬编码租户字段或本地 fallback 进入单用户代码。
- 当前研发资源集中于已有单用户链路的根因修复、交互完整性、真实运行验证和目标平台发布质量。
- 未来企业化需要新增独立服务端与部署体系，不会被描述为一次前端页面或 Gateway 地址选择器改造。

## 被否决的当前方案

### 在 JunQi 本地增加租户和角色表

否决原因：本地状态不能成为远端 Gateway 准入、即时撤权、跨设备身份或租户隔离的权威来源。

### 在同一个 Gateway 中按 `tenantId` 隔离

否决原因：OpenClaw 明确指出 Session 标识是路由选择器，不是租户授权边界；敌对或不共享信任的租户必须使用独立 Gateway。

### 先预留企业接口和页面，后续再接服务端

否决原因：没有服务端契约和真实消费者的类型、开关、页面与 fallback 会形成伪能力和双轨维护负担，违反当前最简单可验证实现原则。

### 直接把共享 Gateway token 下发给企业客户端

否决原因：共享凭据代表该 Gateway 的可信操作员权限，不能提供个人身份、最小权限、即时撤权和审计关联。
