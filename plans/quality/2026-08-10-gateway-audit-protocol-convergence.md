# Gateway 审计协议收敛计划

日期：2026-08-10

## 实施顺序

1. 从 `OpenClawAuditClient.ts` 提取活动审计领域类型和纯协议 codec。
2. 删除 `audit.list` 兼容回退、旧事件解析器、旧 source 联合和无消费者导出。
3. 让请求客户端只负责参数构造、单次 RPC、未知方法映射和 codec 调用。
4. 添加 `active_run_injected`、单请求、未知方法和严格字段相关性的回归测试。
5. 删除当前官方仍已移除的 REM、Talk cancelTurn 和 compaction get 调用链，以及重复内存诊断实现；2026-08-19 已恢复的 voice wake routing set 不再归入该集合。
6. 语音唤醒路由界面仍保持当前只读范围，但不得再以官方缺少写方法作为依据。
7. 全局搜索旧常量、旧解析器、`source: 'legacy'` 和已删除 RPC，确认没有动态或测试消费者。
8. 以最新版官方核心描述符、官方内置插件和 JunQi 插件注册表分别核对生产请求清单。
9. 收敛 Cron 的重复协议类型，按官方 Date 上限校验创建参数和响应时间戳，删除旧状态投影。
10. 删除基于握手方法列表的会话历史前置拒绝，由认证连接和真实 RPC 响应决定状态。
11. 运行定向测试、静态检查、完整测试、生产构建和文本扫描。
12. 更新审计记录与 `PROJECT_STATUS.md`，记录真实 Gateway 和目标平台未验证边界。
13. 解码并暴露当前 Gateway 附件策略，以策略对象统一桌面读取、附件准备、发送前校验和 Quick Chat。
14. 删除附件数量、总量和重复文件上限，补充握手策略缺失、重连替换、逐附件超限和帧超限回归。
15. 补齐官方权限封闭联合，并让日常连接显式请求 Talk 权限。
16. 已完成：删除无消费者的协作会话变更 RPC 和可执行状态机；持久化结构收敛为 schema 15，旧版本数据库失败关闭。
17. 已完成：删除无消费者的 Workbench Provider claim 前后端链路，保留 provider 能力探测。

## 设计边界

- 使用 Gateway requester 端口与纯 codec 的组合，不用继承表达协议变体。
- `audit.list` 和 `audit.activity.list` 是两个独立官方能力，不建立兼容链。
- 业务组件只依赖经过验证的领域投影，不接触原始 Gateway 响应。
- 上游删除的能力直接移除，不增加版本门禁、兼容包装或猜测性回退。
- 官方内置插件方法与 JunQi 自有插件方法分别核对注册来源、权限和生产消费者。
