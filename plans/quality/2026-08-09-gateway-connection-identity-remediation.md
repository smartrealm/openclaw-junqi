# Gateway 连接身份整改计划

日期：2026-08-09

## 根因与影响链

1. `connect` 在判断活动 socket 前写入新目标。
2. 活动 socket 使方法提前返回。
3. 传输仍连接旧 Gateway，连接对象和后续重连却持有新目标。
4. 旧字符串权限回调又让不同入口以不同方式解释同一官方错误。

## 实施顺序

### 第一阶段：失败回归

1. 为活动连接的目标替换增加行为测试。
2. 为同目标重复连接增加幂等测试。
3. 保留既有旧握手异步结果隔离测试。

### 第二阶段：目标切换

1. 提取连接目标值对象及相等判断。
2. 将旧连接失效收敛为单一内部方法。
3. 调整 `connect` 的提交顺序，先判断幂等或切换，再写入新目标。
4. 把直接涉及的英文注释改为中文。

### 第三阶段：权限回调收束

1. 删除 `GatewayCallbacks.onScopeError` 和传输层 fallback。
2. 将快速会话、审批订阅和特权请求入口改为 `onAuthorizationIssue`。
3. 删除无消费者的 `isAuthError` 与专属测试引用。

### 第四阶段：凭据读取收束

1. 将 URL 凭据读取限定为解析出的唯一 runtime key。
2. 删除端点 token 回退和其专属测试。
3. 保留绑定事务与安全存储不可用时的明确状态。

### 第五阶段：验证

1. 运行连接身份、凭据安全、审批订阅、消息路由和快速会话定向测试。
2. 运行 TypeScript 静态检查、模块边界、完整前端测试和生产构建。
3. 执行 `git diff --check`、修改文件完整 Emoji 扫描并更新 `PROJECT_STATUS.md`。
4. 真实 Gateway 目标切换和三平台真机行为保持为独立未验证边界。
