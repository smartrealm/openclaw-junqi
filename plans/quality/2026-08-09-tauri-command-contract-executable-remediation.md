# Tauri Command 可执行契约整改计划

日期：2026-08-09

## 根因

旧测试读取 45 个源码文件并以 132 条正则断言具体文本。该方法不能证明包装器实际传递的参数，也会因重命名、
格式化或职责拆分产生无关失败。

## 实施顺序

1. 保留现有纯解码器测试，作为返回值形态的契约层。
2. 为 Tauri invoke 安装测试期内部桥，记录真实 command 和参数。
3. 覆盖 Gateway、设备签名、钉钉、渠道、通知、语音和媒体等高风险包装器。
4. 删除依赖业务源码片段的历史契约测试。
5. 增加只关注注册关系的生产直接字面量调用守护。
6. 执行定向测试、TypeScript 检查、全量测试、构建和 Rust 验证。

## 实施状态

步骤 1 至 5 已完成。运行时测试覆盖 5 组高风险包装器；静态守护只检查直接字面量调用与 Rust 注册表关系。
完整前端测试、完整 Rust 测试与生产构建已通过；三平台真机验证仍将在真实验收阶段执行。
