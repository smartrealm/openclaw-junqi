# AI 原生交互实施计划

## 实施原则

- 每项改动先确认现有 OpenClaw 或 Tauri 状态来源，再只调整其桌面投影；不新增本地业务语义。
- 按真实用户路径分批交付，每批包含状态、键盘、减少动态效果、窄窗口、亮暗主题和定向测试。
- 优先复用 Aegis token、`LoadingIndicator`、`SceneTransition`、`TabMotion`、Radix 组件及现有
  业务 hook；不增加 UI 或动效依赖。
- 每批结束后删除被替代的视觉实现和专属测试，避免多套输入框、加载器或面板语法并存。

## 批次一：会话主路径

范围：`ChatPage`、`ChatView`、`MessageInput`、`ComposerInputSurface`、`MessageBubble`、
`ToolCallBubble`、响应轨迹及对应测试。

1. 以实际会话状态定义统一的输入、发送、打断、排队、附件、语音和离线反馈，不改变发送、恢复或
   `sessionId` 生命周期。
2. 将流式回复、工具调用和响应轨迹统一为“摘要先出现、真实状态变化后展开、详情按需可见”的布局；
   删除聊天分隔中的无限渐变 shimmer。
3. 对所有可展开项补齐 button 语义、`aria-expanded`、键盘焦点、禁用状态和虚拟列表稳定性验证。
4. 不实现演示式逐词动画、虚构来源、隐藏推理展示或本地推荐卡。

验收：新建空会话可立即输入；历史加载、发送、Stop、工具运行、工具错误、来源缺失、断线和窄窗口
不出现错误状态错配；会话既有回归测试和新增交互测试通过。

完成记录（2026-08-12）：工具调用已补齐 Gateway 状态文字、渐进详情与对应回归测试；思考摘要、
Composer 控件和原生决策区已收敛到轻量 Aegis 表面。快捷回复及内联按钮只记录本地选择，不使用完成
图标暗示 Gateway 成功。会话删除、重置等破坏性变更期间的本地交接消息改为独立“等待会话变更”面板，
与 Gateway 已接纳的消息队列明确分离；普通发送、Gateway 队列模式、Stop、工具调用、审批决策、任务
取消和会话恢复协议均未改变。

## 批次二：安装、Gateway 与渠道控制面

范围：`SetupFlowPanels`、`SetupPage`、`setupStepTransition`、Channels Center 和共享加载状态。

1. 以官方 Wizard、Gateway 生命周期与渠道运行证据为唯一状态来源，统一等待、验证、成功、失败和
   待验证的视觉表达。
2. 收敛步骤器、内容卡、日志和底部操作的高度与切换，确保步骤变化不产生横向滚动或大幅跳动。
3. 将渠道账号的摘要、运行证据、账号绑定、二维码、安装和危险操作整理为一致的层级与操作区。
4. 移除普通业务控件中的渐变和重复 transition；保留主题预览、图表、终端和安全预览的必要例外。

验收：欢迎、环境、存储、运行时、官方配置、就绪各路径的进度与操作对应；官方不支持、未连接、失败
和正在验证状态不被渲染为成功；既有 Wizard 和渠道契约测试加上交互回归通过。

## 批次三：任务、审批、文件和 Jarvis

范围：Activity Center、Task Ledger、Approvals、FilePreview、Jarvis overlay 与设置页。

1. 以共享的摘要行和详情层级收敛 Task Ledger、审批、工具轨迹和文件产物的阅读路径；决策按钮只使用
   Gateway 提供的 allowed decisions。
2. 改善文件预览的加载、错误、截断、外部打开和窄窗口操作锚点，同时保持 iframe sandbox 和
   二进制不可预览语义。
3. 让 Jarvis 覆盖层和设置页复用同样的连接、监听、处理中、可打断、失败和不可用反馈；不增加本地
   唤醒、路由或语音能力。

验收：Task cancel、retry delivery、dismiss、审批选择、文件预览失败和语音停止均保留真实结果；
焦点、Escape、屏幕阅读器状态和减少动态效果可用。

## 批次四：终端、智能体与业务工作台

范围：Terminal、Agent Hub、Agent Workspace、Business Applications、Dashboard、Analytics 及共享
页面壳。

1. 先清理已证明无消费者的演示或旧视觉包装，再将仍有真实消费者的输入、列表、详情和表格迁回
   Aegis token、共享按钮和一致动效。
2. 表格筛选、工作区、终端、智能体和 DWS 页面只展示其已存在的运行时、OpenClaw 或 DWS 投影数据。
3. 将大页面拆为能独立验证的视觉单元，避免为了统一外观改写跨层业务逻辑。

验收：各页面亮暗主题、桌面窄窗口、键盘、空态、加载、失败、数据较多和减少动态效果通过；终端和
业务平台的真实运行边界单独记录。

## 批次五：全局收口与真机验证

1. 审查本轮涉及文件中剩余的硬编码普通业务颜色、无限动画、直接 style 过渡和重复控件壳；仅删除
   已证明被替代且无引用的代码。
2. 执行定向测试、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm test:rust` 和 `git diff --check`。
3. 在 macOS、Windows、Linux 分别记录可执行的真机视觉验收范围；未实测的平台不得宣称完成。

## 实施顺序

先完成批次一，再进行批次二和批次三；批次四依赖前三批确定的共享交互语法；批次五只在前四批的
真实消费者与删除范围可证明后执行。每批开始前更新对应的当前审查记录，完成后回写
`PROJECT_STATUS.md`。
