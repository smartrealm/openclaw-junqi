# 业务审计与模型选择器状态修复计划

## 实施顺序

1. 抽取业务审计的互斥展示状态，并补充错误不得落入空状态的回归测试。
2. 将业务审计空状态、错误状态和操作文案接入三种语言资源。
3. 拆分 Session 模型目录与运行参数滚动边界，保持底部操作固定可达。
4. 仅根据官方未知方法结构化响应判定活动审计不支持；只在官方允许的旧 Gateway 工具审计范围回退到 `audit.list`，并传播账本来源。
5. 将模型弹层接入共享视口碰撞宿主，把目录和参数改成互斥页签，并补充目录筛选与独立滚动。
6. 为文档根节点上的共享菜单宿主显式设置 Tauri 非拖拽区域，保证无边框窗口中的目录滚动和模型选择可达。
7. 运行定向测试、完整前端测试、静态检查和生产构建。
8. 在真实桌面应用连续验证长模型列表、窄窗口、亮色和暗色主题。
9. 将审计页绑定到精确 Session key，保证只有同一 Session 的刷新失败才保留已确认的官方记录。
10. Gateway 断开时同步撤回已读取的审计页与分页状态，避免 effect 尚未运行前短暂发布旧账本。
11. 删除无消费者的旧审计 Hook 与展示组件，避免同一审计概念绕过统一客户端直接调用旧协议。
12. 将高权限临时连接的结构化 scope 拒绝接入统一授权恢复界面，区分可审批请求与需要重新配对的既有设备。

## 未验证边界

- 浏览器验证不能替代 macOS、Windows 和 Linux 的真实 Tauri WebView 验收。
- 本次不改变 OpenClaw 的审计或 Session 运行时协议。

## 当前结果

- 步骤 1 至 6、9 至 12 已完成并通过定向自动化与静态检查验证；2026-08-24 已删除基于 `missing scope: operator.admin` 错误文本的推断性回退，并补齐结构化管理员 scope 拒绝的恢复入口。
- 步骤 8 保留为真实桌面视觉验收项。
