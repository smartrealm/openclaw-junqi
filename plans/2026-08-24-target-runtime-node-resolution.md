# 目标运行环境 Node.js 决策修复计划

## 根因

后端已经按目标 OpenClaw 的 `engines.node` 和目标 Runtime 的 Node/npm 对进行判断，但前端将“不存在可用 Node.js”与“已存在但版本不兼容”合并为同一安装文案，掩盖了正确的兼容性判断。

## 实施顺序

1. 核对最新版 OpenClaw 官方主线的 `engines.node` 与本仓库 Node Runtime 选择路径。
2. 在前端安装步骤中按目标机器探测状态呈现实际 Node 版本和目标范围。
3. 在 Rust 运行时准备进度中传递同一结构化版本和范围，消除后续阶段的泛化提示。
4. 补充纯函数回归测试、三语资源核验、Rust 格式与类型检查，并更新安装流程、审查记录和项目状态。

## 已知边界

Windows、macOS 和 Linux 的版本管理器、PATH 和系统安装器仍需在相应目标机器实测。JunQi 不扫描或采用开发机环境，也不把当前仓库的 Node.js 版本视为目标机器事实。
