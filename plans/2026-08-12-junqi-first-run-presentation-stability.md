# JunQi 首次设置页面稳定性实施计划

## 实施顺序

1. 将 `SetupShell` 收敛为全流程稳定内容布局，移除 `main` 的步骤 key，由页面主内容区统一滚动和复位；步骤卡片不再创建通用滚动边界。
2. 在 `setupStepTransition` 增加内容级短过渡，复用系统减少动态效果和现有 Aegis 动效节奏。
3. 统一存储读取、恢复、应用和就绪页面，并清理运行时前置条件与 Gateway 页面中的重复标题。
4. 统一配置核验、向导连接、官方步骤、提交等待和错误状态的页面骨架。
5. 数据位置步骤默认展开“安装位置”，并复用现有设置草稿保存用户在当前会话中的展开或折叠选择。
6. 移除通用步骤卡片的强制填充高度；普通官方步骤提交时保留并禁用当前内容，授权和自动进度步骤继续按生命周期销毁旧交互并显示紧凑等待状态。
5. 调整短提示、确认和文本输入的内容布局，避免重复 message 和大面积无组织空白。
6. 增加行为回归测试，并同步首次流程预览、质量记录与 `PROJECT_STATUS.md`。
7. 将环境探测与结果复核合并为同一视觉场景，用固定三项骨架隔离中间数据，并等待 OpenClaw、
   Gateway 与 Docker 探针全部收敛后再发布复核结果。
8. 执行定向测试、完整 lint、完整测试、生产构建、`git diff --check` 和 Emoji 扫描。
9. 回归验证欢迎页“下一步、上一步、再下一步”，确认常驻组件不会保留失效的前进单飞锁。

## 验证重点

- `Done` 仍是官方 note，提交后显示等待官方终态，不直接进入完成页。
- 授权二维码只属于当前官方步骤，提交、错误和下一步时不残留。
- 标题区、内容区和底部按钮在欢迎、检测、存储、安装、短步骤、长列表、二维码、日志展开和错误之间
  不改变外层几何边界。
- 亮色、暗色、窄窗口、键盘焦点和减少动态效果分别记录自动化与真机验证范围。
- 桌面版连续抓帧必须覆盖环境探测开始、加载骨架和复核结果三个阶段；加载到结果之间不能出现空白帧、
  整体位移或 Docker 状态晚到造成的二次布局变化。
