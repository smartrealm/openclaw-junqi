# OpenClaw 已发布 Gateway 进度卡兼容实施计划

日期：2026-08-20

## 实施顺序

### 阶段一：协议解码

1. 在进度卡领域层增加官方旧发布计划流的有界解码和临时卡片投影。
2. 收紧 `progressCard.changed.revision` 为正安全整数或 `null`。

### 阶段二：运行事件接入

1. 仅在 `ChatHandler` 已接受官方运行序号并解析出会话归属后发布计划流。
2. 计划流仍进入原有通用事件路径，不抢占后续 Agent 事件序号。

### 阶段三：能力与竞态收敛

1. 以当前连接对 `progressCard.get` 的真实 RPC 结果区分持久化模式和旧发布流模式。
2. 能力未知期间暂存每个会话最后一条计划更新；方法明确不可用后再原子发布。
3. 持久化读取成功后丢弃暂存更新；连接变化时清空全部兼容状态。
4. `revision: null` 直接清空，重复修订不重复读取。

### 阶段四：验证与记录

1. 增加领域解码、事件桥、运行序号和能力竞态回归测试。
2. 运行定向测试、TypeScript 检查、完整测试和生产构建。
3. 更新运行时契约审计与 `PROJECT_STATUS.md`，明确真实运行和目标平台未验证边界。

### 阶段五：空态收敛

1. 删除无真实进度卡时的读取错误占位和无消费者错误状态。
2. 读取失败时保留同一连接内最后一张已核验卡片；此前没有卡片时保持无展示。
3. 删除已无消费者的进度读取错误翻译。
