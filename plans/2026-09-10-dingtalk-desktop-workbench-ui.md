# 钉钉桌面工作台 UI 实施计划

## 实施顺序

1. 添加工具目录选择语义、说明展示、审计证据渐进披露和三语言资源回归测试。
2. 删除独立筛选侧栏与对应宽度、折叠和窗口监听状态，把筛选收敛到目录工具栏。
3. 重构工具表为单一可访问选择入口，删除重复业务域列并提升可扫描层级。
4. 重排详情内容并增加固定操作区，统一 Profile、参数、风险、错误和结果层级。
5. 增加目录与详情的响应式聚焦布局，宽窗口并排、窄窗口单任务切换。
6. 收敛审计摘要和列表正文，把低频技术证据移入按需展开区域。
7. 统一接入页和身份组件的标题、正文、控件、间距与对齐。
8. 补齐简体中文、繁体中文和英文文案，更新项目状态。
9. 运行定向测试、完整测试、lint、生产构建、差异检查和 Emoji 扫描。
10. 完成可用环境内的亮暗主题、窄窗口、键盘与状态序列视觉验证后提交。

## 删除审查

- 删除 `FilterPane`、左侧宽度状态、左侧折叠状态和仅服务于该栏的调整手柄入口。
- 删除窗口宽度监听形成的第二套响应式状态，改由样式断点与现有详情开关共同决定可见区域。
- 保留 `PaneResizeHandle`，因为详情检查器仍有真实消费者。
- 不删除现有 OpenClaw、DWS、事件或审计链路。

## 验证顺序

1. 定向 Node 组件测试和语言资源测试。
2. `corepack pnpm lint`。
3. `corepack pnpm test`。
4. `corepack pnpm build`。
5. `git diff --check`、完整变更文件 Emoji 扫描和 Git 状态核对。
6. 可用环境内连续检查亮色、暗色、窄窗口、键盘焦点、加载、失败和空状态；不能执行的目标平台验收明确记录为未验证。

- 实施步骤 1 至 8 已完成。
- 定向测试、完整测试、lint、生产构建和差异检查已通过。
- 可用浏览器环境已完成静态预览的亮色、暗色、窄窗口和键盘切换验证。
