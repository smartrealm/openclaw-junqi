# Gateway 管理员权限升级实施计划

1. 以更新后的 OpenClaw 官方主线核对会话参数权限和设备 scope upgrade RPC。
2. 为 scope 升级响应校验、令牌持久化顺序、重连身份围栏和业务重试补充失败回归测试。
3. 在 Gateway 服务边界实现单实例权限升级协调器，不在页面或 Hook 中另建 RPC 状态机。
4. 让统一特权请求器在 scope 拒绝后挂起，并在已核验主连接换代后重新捕获身份。
5. 将共享密钥与设备令牌映射到官方各自的握手字段，防止批准后的设备凭据再次进入共享密钥认证通道。
6. 将官方批准权限集合带入轮换令牌的首次验证，成功后再恢复日常最小权限；结构化令牌不匹配时，
   只清理当前端点凭据，并在同一已选 Runtime 内重新签发一次。
7. 将 JunQi 握手身份从官方浏览器专属的 `openclaw-control-ui` 改为正式通用
   `gateway-client` 与 `ui`，避免桌面令牌错误进入浏览器共享认证代次。
8. 扩展现有 PairingScreen，使用户可显式发起升级，并通过官方 Control UI 或另一台已授权设备批准
   Gateway 返回的准确请求；当前设备不执行自我批准。
9. 将会话设置的授权错误映射到本地化恢复语义，避免底层英文错误泄漏。
10. 将所选 Runtime 的首次信任与后续恢复重连拆成独立凭据意图；后续重连优先读取已批准的设备凭据，
    不因进程恢复、插件安装重启或官方配置交接退回共享凭据。
11. 让已核验重连直接查询特权请求器的真实等待状态：有等待者则重试并等真实成功事件，没有等待者
    则清除旧授权提示，不依赖可能在重启或竞速中丢失的页面级批准标记。
12. 区分权限申请拒绝、过期和恢复失败终态，显示本地化错误与重新申请入口，不把终态重新伪装成
    首次申请。
13. 用完整闭环回归覆盖申请、批准、轮换令牌保存、批准权限验证、日常权限恢复和原操作单次重放。
14. 用目标 Gateway 日志定位批准后重复触发的真实方法，隔离主连接与临时特权连接的授权提示入口，
    并让被拒绝的后台可选能力探针在当前连接内停止周期重试。
15. 执行定向测试、lint、生产构建、边界检查、差异检查和 Emoji 扫描。
16. 回写 `PROJECT_STATUS.md`，明确自动化与目标平台实测边界。
