# DWS 授权恢复实施计划

## 根因与影响链路

1. Tauri 后端忠实转发 DWS 标准输出和标准错误。
2. 页面把所有标准错误行增加“错误”前缀，正常 OAuth 进度被误报。
3. 展示字符串被缓存，结构化恢复逻辑无法可靠使用原始事件。
4. 长行参与 Radix 对话框网格最小宽度计算，造成内容越界。
5. DWS 因旧凭据槽位不可读拒绝登录时，界面没有官方安全恢复动作。
6. 浏览器回调成功与本机 token 持久化失败被压缩成一个通用失败状态，用户无法判断网页与本机状态为何冲突。
7. 授权后的结构化核验只检查 `success`，没有要求 `authenticated` 为真。
8. 工具详情要求手填“租户身份”，没有复用 `profile list` 的精确账号；日常切换和单账号退出也没有入口。
9. DWS 没有返回头像时，姓名首字母占位容易被误认为已同步的钉钉头像。
10. 业务审计 Hook 吞掉具体错误并统一设置为 `unavailable`，用户无法判断怎样恢复，也无法区分无记录与账本不可读。
11. `tools.effective` 与 DWS Profile 由业务页挂载后的两个 effect 才开始读取；即使空态语义正确，用户进入页面后仍要等待完整探测。
12. 工具表格逐行重复“账号权限：调用时核验”和“Session：已暴露”，把插件目录渲染得像已授权权限表，同时造成不必要的横向宽度。
13. Chat Markdown 使用 `react-markdown` 默认 URL 转换，DWS 返回的 `dingtalk://` 在渲染阶段被清空；即使保留地址，Tauri Shell 默认打开范围也不允许钉钉协议。既有失败又被静默回退到 WebView `window.open`，用户只看到无响应。
14. DWS 授权对话框在操作活动时忽略关闭事件；取消没有可见的取消中状态，且取消 RPC 额外校验可能已经变化的 Gateway 身份，导致 JunQi 自己创建的 DWS 子进程无法可靠终止。

## 实施顺序

1. 扩展事件缓存，同时保留原始输出事件和中性展示行。
2. 增加纯函数解析器，仅识别 DWS 结构化 `auth` 错误和明确的旧槽位不可读语义，并先补回归测试。
3. 收紧对话框和日志区域的宽高、滚动与断行约束，增加可访问的恢复说明和操作按钮。
4. 在 TypeScript 与 Rust IPC 契约中加入 `resetAuth`，只执行官方重置命令；重置不运行授权状态核验。
5. 为重置命令参数、事件缓存、错误分类和终态文案补测试。
6. 更新质量记录和 `PROJECT_STATUS.md`，执行定向测试、完整静态检查、构建及本地未签名安装包生成。
7. 将授权终态核验按操作类型收紧，并为 Native 与 Docker 共用精确 Profile 参数校验。
8. 用 `profile list` 驱动执行身份选择、当前账号切换和单账号退出；所有持久化账号变更均由 DWS 官方命令拥有。
9. 将缺失头像改为通用占位图标，避免生成未经上游返回的身份图像。
10. 保留 `audit.activity.list` 单一官方协议，按连接、方法、权限、响应和传输错误分类展示恢复条件，不回退到旧审计协议。
11. 按官方源码拆分 DWS 版本探测与账户状态操作的结构化终态：安装核验读取 `version`，账户操作继续要求 `success: true` 及对应终态字段。
12. 收敛顶栏紧凑身份的视觉层级，移除重复用户图标，并对姓名、组织和精确 Profile 做去重选择。
13. 将插件错误和授权结果从顶栏迁入共享接入诊断面板，保留就近错误、状态语义和窄窗口可读性。
14. 增加连接级 DWS 身份预热协调器，在 App 根运行时等待 Gateway 身份和当前 Session 后先读取 `tools.effective`，再核验钉钉运行时工具并调用 DWS 身份探针。
15. 快照按 `connectionId + sessionKey + toolsRevision` 建立请求围栏和单飞复用；切换上下文、断线或工具修订变化时丢弃迟到结果。
16. 业务页删除首屏工具与身份探测 effect，只消费共享快照；手动刷新复用同一协调器并强制刷新工具投影。
17. 收敛工具表格为操作、业务域、效果和风险四个信息维度；账号权限边界集中说明，Session 明确拒绝只在对应操作行展示。
18. 增加共享桌面外部链接运行时，先按协议、主机、路径和危险字符完成分类，再调用 Tauri Shell；钉钉只允许 DWS 已证明的 `action/openapp` 与 `page/link`。
19. 先增加深链渲染、协议拒绝、桌面调用和浏览器失败关闭回归测试，再替换 Chat 与 Markdown 文件预览中的重复打开逻辑。
20. 将 Tauri Shell 的 `open` 校验收紧为官方默认范围加两个钉钉路径，并为真实打开失败补充三种语言的就近提示。
21. 迁移共享外链运行时至 Tauri Opener，保留前端协议分类，并在 capability 中用最小 URL scope 覆盖 HTTP、HTTPS、邮件、电话和两个钉钉深链前缀。
22. 为 DWS 直接工具结果增加严格的审批模板提交入口投影，只消费 `data.templates[].formName` 与 `data.templates[].submitUrl`，复用共享外链打开器并保留原始 JSON 诊断。
23. 将 DWS 取消收敛为本地子进程生命周期动作：关闭活动弹窗即请求取消，启动阶段保留取消意图，取得操作标识后立即取消；界面显示取消中直到终态事件，只有用户通过关闭发起且终态确认为取消时自动收起对话框。
24. 取消 IPC 仅接收精确 `operationId`，后端仅终止当前持有的本地 DWS 子进程；删除会因运行时身份更新阻断取消的额外门禁，不从取消请求推断浏览器或外部授权已经回滚。

## 验证顺序

1. 前端纯函数和缓存定向测试。
2. Rust DWS 单元测试。
3. `pnpm lint`、`pnpm test`、`pnpm build`、`git diff --check`。
4. macOS Apple Silicon 未签名应用与 DMG 构建、DMG 完整性校验。
5. 亮色、暗色、窄窗口、键盘焦点和真实 Keychain 恢复流程若未人工执行，必须明确标记为未验证。
6. 连接预热需覆盖同修订单飞、工具修订变化、连接与 Session 切换、迟到结果丢弃和失效上下文拒绝发布。
7. 外部链接验证需覆盖钉钉两个路径、HTTP 与 HTTPS、危险协议、伪造钉钉主机或路径、控制字符、浏览器环境和 Tauri 调用失败。
8. Opener 迁移需同时验证 JavaScript 调用名、Rust 插件注册、capability scope、前端协议拒绝和 DWS 模板结果的安全投影；真机只验证系统处理器是否被调用，不能把它当作钉钉页面加载成功。
9. DWS 取消验证覆盖启动、运行、取消中三态的活动门禁，关闭动作、IPC 精确参数和 Rust DWS 定向测试；真实 Native、Docker、Windows 与 Linux 授权取消另列为目标平台验收，不以本机浏览器或外部服务结果替代。

## 当前进度

- 第 21 项已完成：旧 Shell 打开调用、Rust 插件注册与 capability 已由 Opener 取代，三个原有普通外链入口也复用同一受限运行时。
- 第 22 项已完成：工具详情仅从完整 DWS 审批模板显示提交入口，点击使用同一 `openDesktopExternalLink` 边界，原始结果继续保留。
- 自动化已完成；真实 Tauri 与钉钉客户端的系统协议处理仍待人工验收。
