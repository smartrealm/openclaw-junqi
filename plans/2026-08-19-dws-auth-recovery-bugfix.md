# DWS 授权恢复实施计划

## 根因与影响链路

1. Tauri 后端忠实转发 DWS 标准输出和标准错误。
2. 页面把所有标准错误行增加“错误”前缀，正常 OAuth 进度被误报。
3. 展示字符串被缓存，结构化恢复逻辑无法可靠使用原始事件。
4. 长行参与 Radix 对话框网格最小宽度计算，造成内容越界。
5. DWS 因旧凭据槽位不可读拒绝登录时，界面没有官方安全恢复动作。
6. 浏览器回调成功与本机 token 持久化失败被压缩成一个通用失败状态，用户无法判断网页与本机状态为何冲突。
7. 授权后的结构化核验只检查 `success`，没有要求 `authenticated` 为真。
8. 工具详情要求手填“租户身份”，没有复用 `profile list` 的精确账号；日常切换和单账号退出也没有入口。
9. DWS 没有返回头像时，姓名首字母占位容易被误认为已同步的钉钉头像。
10. 业务审计 Hook 吞掉具体错误并统一设置为 `unavailable`，用户无法判断怎样恢复，也无法区分无记录与账本不可读。

## 实施顺序

1. 扩展事件缓存，同时保留原始输出事件和中性展示行。
2. 增加纯函数解析器，仅识别 DWS 结构化 `auth` 错误和明确的旧槽位不可读语义，并先补回归测试。
3. 收紧对话框和日志区域的宽高、滚动与断行约束，增加可访问的恢复说明和操作按钮。
4. 在 TypeScript 与 Rust IPC 契约中加入 `resetAuth`，只执行官方重置命令；重置不运行授权状态核验。
5. 为重置命令参数、事件缓存、错误分类和终态文案补测试。
6. 更新质量记录和 `PROJECT_STATUS.md`，执行定向测试、完整静态检查、构建及本地未签名安装包生成。
7. 将授权终态核验按操作类型收紧，并为 Native 与 Docker 共用精确 Profile 参数校验。
8. 用 `profile list` 驱动执行身份选择、当前账号切换和单账号退出；所有持久化账号变更均由 DWS 官方命令拥有。
9. 将缺失头像改为通用占位图标，避免生成未经上游返回的身份图像。
10. 保留 `audit.activity.list` 单一官方协议，按连接、方法、权限、响应和传输错误分类展示恢复条件，不回退到旧审计协议。
11. 按官方源码拆分 DWS 版本探测与账户状态操作的结构化终态：安装核验读取 `version`，账户操作继续要求 `success: true` 及对应终态字段。
12. 收敛顶栏紧凑身份的视觉层级，移除重复用户图标，并对姓名、组织和精确 Profile 做去重选择。
13. 将插件错误和授权结果从顶栏迁入共享接入诊断面板，保留就近错误、状态语义和窄窗口可读性。

## 验证顺序

1. 前端纯函数和缓存定向测试。
2. Rust DWS 单元测试。
3. `pnpm lint`、`pnpm test`、`pnpm build`、`git diff --check`。
4. macOS Apple Silicon 未签名应用与 DMG 构建、DMG 完整性校验。
5. 亮色、暗色、窄窗口、键盘焦点和真实 Keychain 恢复流程若未人工执行，必须明确标记为未验证。
