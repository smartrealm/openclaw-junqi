# 钉钉审批追溯与流程展示实施计划

日期：2026-08-10

## 目标

在现有钉钉业务工作台基础上，增加基于 DWS 真实返回的审批实例、审批任务、流程记录和人工审核展示。JunQi 只做结构化投影，不重新定义钉钉审批状态，也不生成没有上游证据的流程节点。

## 已核对的 DWS 命令

以下命令来自当前 DWS 产品参考，调用时统一使用 JSON 输出，并通过插件的精确 profile 绑定：

| 能力 | DWS 命令 | 作用 |
| --- | --- | --- |
| 可见流程 | `oa approval list-forms` | 获取当前用户可见的审批流程入口 |
| 实例详情 | `oa approval detail --instance-id <ID>` | 获取审批实例当前状态和详情 |
| 审批记录 | `oa approval records --instance-id <ID>` | 获取实例的历史记录和可追溯事件 |
| 待办任务 | `oa approval tasks --instance-id <ID>` | 获取当前用户对指定实例可处理的审批任务 |
| 待审批实例 | `oa approval list-pending` | 获取当前用户待处理审批实例 |
| 已发起实例 | `oa approval list-submitted` | 获取当前用户发起的审批实例 |
| 同意 | `oa approval approve --instance-id <ID> --task-id <TASK_ID>` | 处理指定审批任务 |
| 拒绝 | `oa approval reject --instance-id <ID> --task-id <TASK_ID>` | 拒绝指定审批任务 |
| 撤销 | `oa approval revoke --instance-id <ID>` | 撤销本人发起的审批 |

`instanceId`、`taskId`、`processCode` 等标识只能从前一步的结构化返回中取得，禁止在客户端生成或拼接。

## 当前差距

- 当前插件已经注册审批表单、待审批、已提交、详情、表单字段以及审批写入工具。
- 当前插件没有独立的审批任务和审批记录工具，不能可靠支撑流程节点和人工审核时间线。
- 当前业务页是通用工具表格和 JSON 结果面板，没有审批实例列表、流程时间线或节点详情组件。
- 当前审计页只能展示 OpenClaw 工具调用 metadata，不能替代 DWS 的审批记录。
- 当前没有真实 DWS 租户返回样本，无法证明详情、任务和记录中的字段名称、节点层级及状态枚举。

## 实施顺序

### 阶段一：补齐能力契约

1. 通过 DWS schema 重新核验审批任务、记录、详情、列表命令的 canonical path、参数、效果、风险、确认和幂等属性。
2. 仅在 schema 核验通过后新增固定插件工具，不提供任意 DWS 命令入口。
3. 为新增工具补充 allowlist、schema 漂移、参数校验、输出错误和权限失败测试。
4. 记录 DWS 版本、schema 摘要和未验证字段，不把版本号作为永久能力开关。

### 阶段二：建立审批领域投影

新增单一职责的审批投影模块，分离命令结果、领域投影和展示模型：

- 实例摘要：只使用 DWS 实际返回的实例标识、流程标识、标题、申请人、状态和时间字段。
- 审批任务：只使用 DWS 实际返回的任务标识、实例标识、处理人、任务状态、动作、备注和时间字段。
- 审批记录：保留 DWS 返回的记录顺序、事件类型、操作者、结果和时间；缺字段显示“DWS 未返回”。
- 证据关联：绑定 runtime identity、session identity、profile、schema digest、tool call、run 和 observedAt。
- 状态映射：只映射已在真实 DWS 返回或 schema 中证明的状态；未知状态保留原值并标记“待核验”。

禁止从本地按钮点击、OpenClaw 工具完成或空数组推断审批节点已通过、审批已结束或审批已回滚。

### 阶段三：审批 UI

在“业务应用”内增加审批专用展示，复用现有主题 token、按钮、空状态、错误状态和可收起面板：

1. 审批实例列表：待我审批、我发起的和可见流程分区由真实工具结果驱动。
2. 审批详情：展示实例概要、表单字段摘要、当前状态、身份和观察时间。
3. 流程时间线：以 DWS 审批记录为唯一数据源；有节点记录才绘制节点，无记录时显示明确空状态。
4. 人工审核节点：展示 DWS 返回的任务处理人、动作、备注、时间和结果；不把 OpenClaw 插件审批误显示为钉钉人工审批。
5. 操作入口：同意、拒绝、撤销均从真实实例和任务标识进入统一确认、OpenClaw 审批、DWS 执行和权威重读链路。
6. Chat 预览：当 Chat 收到可验证的审批结构化结果时，复用同一审批投影和详情面板；没有结构化字段时只展示通用结果，不伪造流程图。

### 阶段四：追溯闭环

- 业务活动记录保留工具调用与审批操作的最小脱敏元数据。
- 审批详情和记录作为钉钉实体权威来源，不能由本地活动投影替代。
- 写操作成功后重新读取实例详情和记录；无法读取时进入“结果待核验”。
- 断线、超时、取消或未知结果禁止自动重放非幂等审批动作。
- DWS 返回恢复事件时只展示正式 recovery 入口，不自行完成恢复。

## 验收条件

- 没有真实审批记录时，页面显示真实空状态，不显示示例节点。
- 返回字段缺失、状态未知、权限不足、认证过期、Gateway 断开和 DWS schema 漂移均有独立错误状态。
- 亮色、暗色、窄窗口、键盘焦点、加载、失败和长列表滚动均完成桌面走查。
- 插件、投影解析、状态映射、审批确认、待核验和 Chat 复用均有回归测试。
- 真实 DWS 租户和正式发布包验证单独记录，不能用单元测试或静态设计预览替代。

## 当前结论

已完成第一阶段的可验证闭环：插件暴露官方审批记录、审批任务和流程预测工具；业务页从详情、记录和任务结果建立同一实例的脱敏追溯投影，并提供用户主动的“刷新追溯”读取入口。刷新只调用 OpenClaw 当前 Session 报告为有效的只读工具，部分工具失败时保留成功结果并显示真实错误，不生成推测节点。真实 DWS 租户字段、权限、状态枚举和桌面视觉仍待验证，后续只能基于脱敏结构化样本扩展字段。
